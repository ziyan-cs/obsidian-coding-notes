# 依赖图而非依赖列表

直接依赖还会引入传递依赖：

```text
application
|-- library-a -> common-x 1.x
`-- library-b -> common-x 2.x
```

解析器需要处理版本约束、平台条件与冲突。升级一个顶层包可能改变整张依赖图，因此锁文件应与源码一起评审。

# 三类版本信息

- 版本范围：表达兼容承诺，例如允许补丁升级。
- 锁定版本：记录当前已解析的精确结果。
- 内容摘要：确认下载内容没有被替换或损坏。

仅写“最新版”会让历史提交无法稳定重建；仅固定库版本但不记录工具链，也可能产生不同二进制。

# 可复现构建边界

至少记录：

- 编译器、解释器、构建工具及重要选项。
- 操作系统基础镜像或系统包版本。
- 第三方依赖版本、来源和校验信息。
- 代码生成器、时区、locale 与影响产物的环境变量。

构建时间戳、随机顺序和绝对路径也可能进入产物，使字节级结果不同。

# 供应链风险

- 名称相似包与依赖混淆。
- 上游账号或发布流程被攻破。
- 构建脚本在安装阶段执行非预期代码。
- 私有镜像长期不更新，积累已知漏洞。

应使用可信仓库、最小权限凭据、摘要校验、依赖审计与升级窗口；不要把“能下载”视为“可信”。

# 最小验证

- [ ] 清空构建目录后完整重建。
- [ ] 在 CI 或容器中关闭本机缓存再构建。
- [ ] 输出依赖图并解释一个传递依赖的来源。
- [ ] 对产物记录摘要，比较两次构建差异。
