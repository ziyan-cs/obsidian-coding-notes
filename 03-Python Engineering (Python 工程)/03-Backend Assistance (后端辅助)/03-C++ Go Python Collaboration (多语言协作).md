# 03-C++ Go Python Collaboration (多语言协作)

> [!abstract] 一句话结论：按问题的约束选语言：C++ 负责底层控制与性能，Go 负责后端服务交付，Python 负责自动化和数据工具；同一项目应让它们协作而不是竞争。

| 任务 | 首选 | 原因 | 不首选的原因 |
| --- | --- | --- | --- |
| 高性能网络核心、现有 C++ 基础设施 | C++ | 资源/内存/延迟控制细 | 开发与维护成本更高 |
| 业务 HTTP/gRPC 服务 | Go | 并发、部署与标准库平衡 | 不为极限性能而手写底层 |
| API 回归、日志分析、数据生成 | Python | 快速表达、生态和脚本能力 | 不承担高并发常驻核心路径 |
| 竞赛算法 | C++ | STL、性能、校招常用 | Python 可用于验证思路 |

## 项目协作示例

```text
Go todo-api  ← Python: 接口回归、测试数据、日志报表
      ↑
C++：如需研究连接管理/性能，做独立实验或底层组件
```

不要为了“技术栈丰富”把一个小项目拆成三种语言。先令每个部件的职责清楚、可测试、可部署。

> [!warning] 面试里不要只说“Python 慢”
> 语言选择应回到约束：吞吐、尾延迟、部署复杂度、现有基础设施、团队熟悉度与可观测性。没有测量和场景的性能判断，无法形成工程决策。

## 30 秒回答

当前学习主线是 C++ 打底、Go 构建后端服务、Python 承担测试和自动化。选型不是排名赛：在一个小项目里优先单语言做出完整可演示闭环；只有边界、收益和维护责任明确时，才引入第二种语言。

## 自测

1. 给“Go 服务 + Python 回归脚本”划出 API、失败处理和版本责任边界。
2. 什么时候 C++ 实验应独立于业务服务，而不是直接嵌进项目？



## 从零建立模型

本页主题是 **03-C++ Go Python Collaboration (多语言协作)**。Python 对初学者最重要的是区分“值、名称、对象”和“副作用”。函数拿到什么输入、返回什么值、会读写哪些文件/网络资源，应该从签名和小例子中一眼可见。先写可读的同步代码，再为真实 I/O 或批量任务引入并发。

## 最小实践

把本页概念做成一个可运行函数或 CLI：准备正常、空值和错误输入各一份；打印或断言结果。若涉及文件和网络，使用临时目录或 test double，不能依赖本机隐式状态。

## 工程检查点

Python 的动态性不等于不需要契约。公共函数应写类型标注、异常语义和示例；密钥、绝对路径、真实生产数据都不应写死在示例里。



## 渐进练习

1. **第一步 · 理解**：读：用自己的话区分本页的输入、返回值与副作用。
2. **第二步 · 实现**：写：实现一个不依赖真实网络或用户目录的小函数，并为正常、空值、错误输入各写一个测试。
3. **第三步 · 验证**：改：故意让外部边界失败，检查异常信息、日志和退出码是否足够定位。

## 常见误区

- 把脚本一次跑通当成工程正确，忽略环境隔离、输入校验、错误分类和可重复运行。
- 只读 API 名称而不为文件、网络、时间等外部边界写一个可控测试。
