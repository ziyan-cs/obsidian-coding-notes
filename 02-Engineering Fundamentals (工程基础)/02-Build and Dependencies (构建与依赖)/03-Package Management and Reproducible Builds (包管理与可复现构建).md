> [!abstract] 学习定位
> > 可复现构建要求同一源码、工具链与依赖输入产生可验证的等价产物；包管理解决依赖获取，但不能替代版本、来源和构建环境治理。

> [!summary] 核心摘要
>
> 依赖声明描述允许范围，锁定结果记录一次解析出的精确版本；构建还受到编译器、标准库、系统包、环境变量和生成步骤影响。工程上要固定关键输入、校验来源、隔离构建环境，并在 CI 中从空缓存验证。

# 依赖图而非依赖列表

直接依赖还会引入传递依赖：

```text
application
|-- library-a -> common-x 1.x
`-- library-b -> common-x 2.x
```

解析器需要处理版本约束、平台条件与冲突。升级一个顶层包可能改变整张依赖图，因此锁文件应与源码一起评审。

# 三类版本信息

- 版本范围：表达兼容承诺，例如允许补丁升级。
- 锁定版本：记录当前已解析的精确结果。
- 内容摘要：确认下载内容没有被替换或损坏。

仅写“最新版”会让历史提交无法稳定重建；仅固定库版本但不记录工具链，也可能产生不同二进制。

# 可复现构建边界

至少记录：

- 编译器、解释器、构建工具及重要选项。
- 操作系统基础镜像或系统包版本。
- 第三方依赖版本、来源和校验信息。
- 代码生成器、时区、locale 与影响产物的环境变量。

构建时间戳、随机顺序和绝对路径也可能进入产物，使字节级结果不同。

# 供应链风险

- 名称相似包与依赖混淆。
- 上游账号或发布流程被攻破。
- 构建脚本在安装阶段执行非预期代码。
- 私有镜像长期不更新，积累已知漏洞。

应使用可信仓库、最小权限凭据、摘要校验、依赖审计与升级窗口；不要把“能下载”视为“可信”。

# 最小验证

- [ ] 清空构建目录后完整重建。
- [ ] 在 CI 或容器中关闭本机缓存再构建。
- [ ] 输出依赖图并解释一个传递依赖的来源。
- [ ] 对产物记录摘要，比较两次构建差异。

# 依赖图与制品证据

可复现构建要求相同源码、依赖、工具链和构建参数能够生成可比较的制品。版本约束只描述允许范围，lockfile 或解析清单记录实际选择；原生依赖还受到编译器、标准库、ABI、目标平台和系统库影响。

工程上保存源码提交、依赖锁定文件、编译器/镜像 digest、构建命令、环境变量白名单、制品哈希与 SBOM。缓存必须把所有影响输出的输入纳入 key，否则命中缓存也可能得到错误制品。升级依赖时检查变更日志、兼容性、许可证和漏洞可达性，并通过测试与渐进发布验证，而不是只看安装成功。
