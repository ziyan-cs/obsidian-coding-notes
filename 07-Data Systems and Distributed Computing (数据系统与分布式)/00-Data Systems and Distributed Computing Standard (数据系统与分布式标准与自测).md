> [!abstract] 完成标准
> 数据与分布式模块不以记产品命令为目标，而以理解一致性、持久化、并发控制、故障恢复和容量边界为目标。

# SQL 与 MySQL

- [ ] 能编写可靠的查询、连接、聚合和数据修改语句，并解释 NULL、约束和事务边界。
- [ ] 能解释 B+Tree 索引、联合索引、覆盖索引、回表与优化器选择。
- [ ] 能说明隔离级别、MVCC、undo/redo log、锁和崩溃恢复之间的关系。
- [ ] 能使用 EXPLAIN、慢日志和运行指标定位查询或锁等待问题。

# 缓存与代理

- [ ] 能根据数据结构、过期、淘汰、持久化和复制语义正确使用 Redis。
- [ ] 能设计缓存更新策略，并处理穿透、击穿、雪崩、热点和一致性窗口。
- [ ] 能说明反向代理、负载均衡、健康检查、限流和连接复用的作用边界。
- [ ] 能评估缓存命中率、内存、延迟、热 key 与故障降级，而非把缓存当作默认答案。

# 消息与流

- [ ] 能解释 producer、broker、consumer、partition、offset 和 consumer group。
- [ ] 能区分 at-most-once、at-least-once 和所谓 exactly-once 的实现边界。
- [ ] 能通过幂等、去重、重试、死信和顺序约束处理真实失败。
- [ ] 能依据吞吐、延迟、积压、保留和消费语义选择消息方案。

# 分布式基础

- [ ] 能解释复制、分片、一致性、可用性、共识、租约和故障检测的基本权衡。
- [ ] 能设计超时、重试、退避、熔断、限流和幂等，避免重试风暴。
- [ ] 能说明分布式锁、唯一 ID、配置中心和服务发现的正确性前提。
- [ ] 能在网络分区、节点宕机、消息重复和时钟不可靠时推演系统行为。

# 综合自测

1. RR 隔离级别下 Read View 何时创建，当前读与快照读有何不同？
2. 缓存更新失败时，怎样界定允许的不一致窗口并完成修复？
3. 消费者处理成功但提交 offset 失败，会发生什么，业务如何兜底？
4. 一个“分布式锁”需要哪些假设，服务暂停或租约过期时怎样防止旧 owner 写入？
