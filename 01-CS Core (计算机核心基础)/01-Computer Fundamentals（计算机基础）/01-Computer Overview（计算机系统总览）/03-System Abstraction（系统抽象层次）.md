> **核心考点**：计算机系统的层次抽象模型、每层屏蔽下层细节、抽象是控制复杂度的核心手段

## 抽象层次模型

每一层**隐藏下层实现细节**，仅暴露接口给上层：

```
┌──────────────────────────────────┐
│         应用程序 (App)            │  ← 高级语言
├──────────────────────────────────┤
│          标准库 (libc)            │  ← API 抽象
├──────────────────────────────────┤
│         系统调用接口               │  ← 用户态↔内核态
├──────────────────────────────────┤
│       操作系统内核 (OS Kernel)     │  ← 进程/内存/文件
├──────────────────────────────────┤
│         指令集架构 (ISA)           │  ← 机器指令
├──────────────────────────────────┤
│         微架构 (Microarchitecture) │  ← 流水线/乱序
├──────────────────────────────────┤
│            逻辑电路               │  ← 布尔逻辑门
├──────────────────────────────────┤
│            晶体管                 │  ← 开关/放大器
└──────────────────────────────────┘
```

## 抽象的好处与代价

| 好处 | 代价 |
|------|------|
| 管理复杂度 | 性能开销（函数调用、上下文切换） |
| 可移植性 | 信息隐藏（无法利用底层优化） |
| 模块化独立演进 | 抽象泄漏（下层限制渗透到上层） |

> **工程要点**：**所有非平凡抽象都是有泄漏的**（Joel 定律）。理解底层有助于写出更好的上层代码。
