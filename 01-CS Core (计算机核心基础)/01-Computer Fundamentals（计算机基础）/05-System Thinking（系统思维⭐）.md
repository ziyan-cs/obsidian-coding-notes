> **核心考点**：局部性原理、空间/时间局部性、缓存友好的代码、并发与并行的区分

## 局部性原理

程序倾向于在一段时间内集中访问某些数据或指令：

| 类型 | 含义 | 例子 |
|------|------|------|
| **时间局部性** | 刚访问过的数据很可能再次被访问 | 循环变量、计数器 |
| **空间局部性** | 刚访问过的数据附近也可能被访问 | 数组顺序遍历 |

```cpp
// 缓存友好（空间局部性好）：顺序访问
for (int i = 0; i < n; i++)
    sum += a[i];          // 一次 cache line（64B）加载 16 个 int

// 缓存不友好：跳跃访问
for (int i = 0; i < n; i++)
    sum += a[big_jump[i]]; // 每次可能在不同 cache line

// 更严重的：按列遍历行主序数组
for (int j = 0; j < n; j++)     // ❌ 每步跨一整行，空间局部性极差
    for (int i = 0; i < n; i++)
        sum += matrix[i][j];
```

## 并发 vs 并行

| 概念 | 定义 |
|------|------|
| **并发** (Concurrency) | 多个任务在**同一时间段内**交替执行（逻辑同时） |
| **并行** (Parallelism) | 多个任务在**同一时刻**同时执行（物理同时） |

单核 CPU 可以并发但不能并行；多核 CPU 可以并发且可以并行。

## 缓存友好编程原则

1. **顺序访问内存**（利用空间局部性）
2. **将热点数据紧缩存放**（struct 中频繁访问的字段放一起）
3. **分治时优先切分数据而非任务**（保持每个子任务的数据局部性）
4. **避免 false sharing**（多线程写同一 cache line 的不同变量 → 性能暴跌）

## 权衡思维

计算机科学的核心就是权衡（Trade-off）：

| 权衡 | 典型场景 |
|------|---------|
| 时间 vs 空间 | 缓存 vs 内存，压缩 vs 原始 |
| 延迟 vs 吞吐 | 批处理 vs 实时处理 |
| 一致性 vs 可用性 | CAP 定理 |
| 精度 vs 速度 | float vs double，近似算法 |
| 通用 vs 专用 | CPU vs GPU vs ASIC |

> **工程要点**：系统思维意味着理解"没有免费的午餐"——每项优化都有代价，关键是识别真正的瓶颈（Amdahl 定律），并从多层级（算法→代码→编译→架构）分析问题。
