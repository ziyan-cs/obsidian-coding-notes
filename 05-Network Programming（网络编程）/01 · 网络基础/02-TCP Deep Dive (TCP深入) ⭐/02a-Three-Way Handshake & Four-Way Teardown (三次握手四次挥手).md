# Three-Way Handshake & Four-Way Teardown

## 三次握手
#network #tcp #three-way-handshake #connection-establishment

## ⚡ TL;DR（快速决策）

- 三次握手的核心是：**让通信双方确认彼此的发送与接收能力，并建立初始序列号同步**
- 典型流程：
    - SYN
    - SYN+ACK
    - ACK
- 它不是“形式主义”，而是 TCP 建立可靠连接所必需的状态协商过程

## 🧩 Core Idea（核心本质）

- TCP 是面向连接协议，双方必须先建立共同上下文
- 三次握手解决的是“双方是否都准备好通信”的问题
- 一句话理解：
    - **三次握手是 TCP 连接建立时的双向确认机制。**

## 🏗️ 三步流程

1. 客户端发送 SYN

- 表示希望建立连接，并给出初始序列号

1. 服务端返回 SYN+ACK

- 表示收到请求，并同意建立连接，同时返回自己的初始序列号

1. 客户端返回 ACK

- 表示收到服务端确认，双方进入已建立连接状态

## 🔧 Usage Patterns（可复用理解框架）

1. 用“双向确认”理解三次而不是两次

- 两次只能确认一方收到
- 三次才能确认双方收发链路都基本可用

1. 用“状态同步”理解握手

- 除了问候，更重要的是同步序列号和连接状态

## ⚠️ Pitfalls（高频错误）

- 只背 SYN/ACK 名字，不理解其确认意义
- 误以为两次握手足够
- 把三次握手和四次挥手混淆

## 🚀 Performance / Tips（理解深化）

- 握手带来额外 RTT 成本，但换来可靠连接语义
- 理解三次握手后，更容易读懂连接队列、半连接、SYN flood 等问题

## 🧪 Common Scenarios（常见使用场景）

- 浏览器建立 TCP 连接
- 服务端监听和 accept 流程
- 抓包分析 TCP 建连过程

## 🧾 Minimal Template（最小理解模板）

```
客户端 SYN -> 服务端 SYN+ACK -> 客户端 ACK
```

## 📌 One-liner Summary（一句话总结）

- **三次握手的核心，是通过双向确认和状态同步建立 TCP 可靠连接。**
## 四次挥手
#network #tcp #four-way-termination #connection-close

## ⚡ TL;DR（快速决策）

- 四次挥手的核心是：**TCP 双方分别关闭各自的发送方向，因此断开连接通常需要四次交互**
- 典型流程：
    - FIN
    - ACK
    - FIN
    - ACK
- TCP 连接是全双工的，关闭时两条方向需要分别处理

## 🧩 Core Idea（核心本质）

- 建立连接时强调双方准备好通信
- 断开连接时强调双方分别完成发送结束确认
- 一句话理解：
    - **四次挥手是 TCP 对双向关闭过程的确认机制。**

## 🏗️ 四步流程

1. 一方发送 FIN

- 表示自己不再发送数据

1. 对方返回 ACK

- 确认收到关闭请求

1. 对方处理完剩余数据后发送 FIN

- 表示自己也准备关闭发送方向

1. 最后一方返回 ACK

- 连接进入关闭流程结束阶段

## 🔧 Usage Patterns（可复用理解框架）

1. 用“全双工”理解为什么要四次

- 两个方向的关闭不能总是合并成一次完成

1. 用 TIME_WAIT 理解最后确认

- 最后一方通常会进入 TIME_WAIT，确保最后 ACK 可重传、旧报文不过度干扰新连接

## ⚠️ Pitfalls（高频错误）

- 把四次挥手和三次握手的目的混在一起
- 误以为关闭连接一定立即完成
- 不理解 TIME_WAIT 的工程意义

## 🚀 Performance / Tips（理解深化）

- 大量短连接系统中，TIME_WAIT 和连接关闭开销非常重要
- 理解四次挥手后，更容易理解连接释放、半关闭、端口占用等现象

## 🧪 Common Scenarios（常见使用场景）

- 分析连接关闭抓包
- 理解服务器短连接行为
- 理解 TIME_WAIT 与端口复用问题

## 🧾 Minimal Template（最小理解模板）

```
FIN -> ACK -> FIN -> ACK
双向分别关闭
```

## 📌 One-liner Summary（一句话总结）

- **四次挥手的核心，是对 TCP 双向发送通道分别完成关闭确认。**
