# Sources & Freshness Policy — 来源与时效性

> 原理笔记追求正确且稳定；工具、版本、API 与生态笔记必须可追溯且标记验证日期。

## 来源优先级

1. **一手来源**：语言标准、官方文档、官方 release notes、源码与 RFC。
2. **权威实现资料**：项目官方博客、维护者演讲、论文。
3. **二手资料**：书籍、课程、社区文章，只用于辅助理解，不能单独支撑易变结论。

## 哪些内容必须标记 `verified`

- 语言/编译器/解释器版本与特性。
- 工具命令、依赖管理、框架 API、云产品与价格。
- 性能数据、兼容性、最佳实践、招聘市场结论。

稳定的基础原理（如 TCP 握手、RAII 基本模型）不必为了日期重复重写，但发现矛盾时必须回查一手来源。

## 笔记末尾来源模板

```md
## Sources
- 官方文档：<title> — <url>
- 验证日期：YYYY-MM-DD
- 适用版本：Go 1.x / Python 3.x / C++17 等
```

## 更新触发器

- 新版本发布、依赖升级、命令失效。
- 你的实际项目出现与笔记冲突的行为。
- 面试或代码 review 中无法解释一个断言。

更新时补一条简短变更说明：`2026-09-05：将 X 的适用版本从 A 更新为 B，原因：官方 release note。`

## AI 内容校验规则

- AI 适合生成初稿、例子、问题清单；不把它当唯一事实来源。
- 涉及并发、内存、安全、性能或版本差异的代码，必须运行或查一手资料。
- “看起来合理”但没验证的内容标记为待验证，不伪装成结论。
