> [!abstract] 学习定位
> 语言模型根据上下文预测 token 分布；embedding 表达可计算的语义相似度，但两者都不保证事实正确。

> [!summary] 核心摘要
>
> 文本被 tokenizer 转成 token，模型在有限上下文中生成概率分布；采样影响稳定性。embedding 适合检索候选，不等于理解、授权或事实判断。

# Token 与上下文

token 不是字符或单词的固定同义词，不同模型 tokenizer 不同。系统指令、检索片段、工具结果和历史消息共同占用上下文；窗口变长会增加延迟、内存和费用，也可能让关键信息被噪声淹没。

上下文超限时需要截断、摘要或分层记忆。策略必须知道哪些指令、证据和用户数据不能丢失。

做容量估算时把系统说明、历史、检索片段、工具结果和预留输出分别计入预算，而不是只数用户问题。输入很短但检索返回十段长文时，真正占窗口的是证据；若保留错误的旧对话而截掉当前证据，模型可能给出流畅却过期的答案。先用目标模型的 tokenizer 测量，再在服务端设置输入与输出上限。

# 生成与不确定性

模型输出来自条件概率分布。temperature、top-p 等参数改变采样，但低温不等于事实正确，高温也不等于随机无用。同一输入可能因模型版本和服务实现变化而得到不同输出。

后端应把模型响应当作不可信建议：验证结构、权限、事实来源和业务不变量。

# Embedding 与相似度

embedding 把对象映射到向量空间，常用余弦相似度或点积寻找邻近候选。结果受模型、切分、语言、领域和归一化影响。

“相似”不等于“答案正确”。向量检索通常需要元数据过滤、重排、权限检查和回答引用。

# 最小实验

选择十段已知主题文本，尝试不同切分长度和查询，观察 top-k 命中。记录模型版本、距离函数和测试集，不用几个成功示例宣称方案有效。

# 最小数学直觉

自回归模型在第 `t` 步估计条件分布 `P(token_t | token_1 ... token_{t-1})`。模型产生 logits，经 softmax 转为概率；temperature 改变 logits 的相对尺度，top-p/top-k 再限制候选集合。它们控制生成分布，不会为输出增加外部事实证据。

embedding 是固定维度向量。余弦相似度比较方向：

~~~text
cos(a, b) = (a · b) / (||a|| × ||b||)
~~~

若向量已归一化，点积与余弦排序等价；未归一化时不能想当然混用。距离阈值没有跨模型、跨数据集的通用值，换模型后必须重建索引并重新评估。

示例：查询“撤销 API 密钥”，文档 A 讲密钥轮换，文档 B 讲撤销令牌。A 与查询在词面上可能更接近，但如果用户需要“立即失效”，B 才是正确证据。向量分数只决定候选顺序；时间条件、业务动作和权限仍须由检索过滤、重排及最终验证处理。

# 切分与检索实验

切分策略要同时保留语义完整性和定位粒度。固定字符数简单但可能截断代码块或论证；按标题和段落切分更符合文档结构，再用适量 overlap 保存跨边界信息。元数据至少包括来源、版本、租户/权限、更新时间和稳定文档 ID。

建立带标准答案的查询集，包含正常问题、同义表达、否定问题、相似但错误的干扰文档和无答案问题。对检索层记录 recall@k、MRR 或 nDCG，对最终回答另测引用正确率、答案支持度与拒答质量。只看几个 demo 无法判断系统是否可靠。

一次可复现的对照实验：固定查询集，分别改变 chunk size、overlap、embedding 模型、top-k 与是否重排；保存索引版本和每次结果，分析哪类问题改善、哪类退化，而不是只汇报平均分。

# 工程失败模式

- tokenizer 变化会改变 token 预算、截断位置和费用，模型升级时必须回归长输入。
- 多语言、代码、数字和专有名词的切分与向量质量可能不同，需要覆盖真实数据。
- 相似度高的文本可能在时间、主体或否定关系上相反，必须让重排和业务校验看到这些字段。
- embedding 和 RAG 不解决 prompt injection；检索内容仍是不可信数据，不能覆盖系统权限与工具策略。
- 摘要式记忆会丢细节，原始证据应可追溯，不能让模型摘要成为唯一事实源。
