> [!abstract] 完成标准
> 面向后端工程师：能把模型作为有概率、有限上下文、昂贵且可能失败的依赖，构建可评估、可观测、受权限约束的生产系统。

# 基础理解

- [ ] 能解释 token、embedding、上下文、训练、推理和采样的工程含义。
- [ ] 能区分模型能力、应用编排、检索数据和运行基础设施。
- [ ] 能验证结构化输出，而不是解析自由文本猜测结果。

# 应用与 Agent

- [ ] 能设计 RAG 的切分、索引、检索、重排、引用和评估流程。
- [ ] 能为工具调用定义权限、schema、幂等、timeout 和人工审批。
- [ ] 能区分 prompt injection、数据泄漏、不安全输出和过度授权。
- [ ] 能构建带来源、版本、权限与风险切片的离线数据集，防止训练/测试泄漏。
- [ ] 能为检索、生成、工具和端到端任务选择指标，并校准人工与自动评分器。
- [ ] 能用 shadow、canary、A/B 与护栏指标发布，识别线上反馈的选择偏差。

# 基础设施

- [ ] 能解释批处理、并发、缓存和上下文长度如何影响吞吐、延迟与成本。
- [ ] 能设计队列、过载保护、重试预算、降级和多模型路由。
- [ ] 能关联检索、模型、工具、token、费用与 trace。
- [ ] 能说明 GPU 调度、模型加载和多租户隔离的基本矛盾。

# 综合自测

1. 设计带引用的内部知识问答服务，说明数据更新、评估和权限边界。
2. Agent 获得数据库与工单工具后，如何阻止提示注入诱导越权操作？
3. P99 与费用同时上升时，怎样区分上下文增长、排队、模型变慢和重试放大？
4. 为什么合法 JSON 仍可能是错误或危险结果？
5. 一个 RAG 新版本总分提高但跨权限样本退化，是否允许发布？怎样设计门槛与回滚？
6. Go、Python、C++ 分别适合承担哪些组件？
