> [!abstract] 学习定位
> RAG 的质量由数据、切分、过滤、召回、重排和引用共同决定；向量数据库只是其中一个组件。

> [!summary] 核心摘要
>
> 文档先解析、切分、附加权限与版本元数据，再建立索引。查询时先按身份过滤，召回候选并重排，回答必须引用证据并能在无证据时拒答。

# 索引流水线

~~~text
source -> parse -> normalize -> chunk -> metadata and ACL
       -> embed -> index -> version -> quality checks
~~~

切分应尽量保留语义边界和来源位置。过大降低定位精度，过小丢失上下文。表格、代码和扫描 PDF 需要不同解析策略。

数据更新要处理新增、修改、删除和权限变化。旧 chunk 不删除会让过期内容继续被检索；索引版本必须可追踪和回滚。

# 查询路径

先执行租户、权限、时间和文档类型过滤，再做关键词/向量混合召回。top-k 不是越大越好；过多低质量片段占用上下文并干扰答案。

重排器提高候选排序，但增加延迟与费用。最终 prompt 保留来源 ID，让回答能返回引用并支持核验。

# 失败模式

- 检索不到：数据未入库、切分错误、查询表达差或过滤过严。
- 检索到了但回答错：上下文冲突、模型未遵循证据或输出校验不足。
- 越权泄漏：过滤发生在检索之后，或缓存未包含权限维度。
- 内容过期：索引更新和源数据版本脱节。

# 检索机制与可诊断评估

向量相似度适合语义召回，关键词检索擅长精确术语、编号和错误码；混合检索再由 reranker 排序。embedding 模型、距离度量和索引参数必须作为索引版本的一部分，不能替换模型后继续解释旧向量。

评估分层：先测目标证据是否进入 top-k，再测排序和 ACL，最后测回答是否忠于证据。检索失败时查看 query、过滤后候选数、各阶段 score 和最终 chunk，而不是只调整 prompt。

切分实验至少比较 chunk 大小/重叠、标题层级、表格代码策略和 top-k；保存不可回答、冲突文档、过期版本及权限样本。缓存 key 包含租户、权限、索引和模型版本。

参考：[NIST IR 8496: Cybersecurity and Privacy Reference Tool for GenAI](https://csrc.nist.gov/pubs/ir/8496/ipd)。

# 评估

构建包含问题、期望证据和不可回答样本的数据集。分别测 retrieval recall、排序质量、引用正确性、回答忠实度、延迟与成本，避免用一个总分掩盖问题来源。

> [!question]- 理解检查
> 为什么权限过滤必须在召回前或检索层执行，而不能把越权片段交给模型后要求它不要回答？
# 检索质量与数据治理

RAG 的数据路径是采集、解析、切分、元数据、embedding、索引、过滤、召回、重排与引用。每一步都要有版本和失败记录；文档删除或权限变化时，索引与缓存必须及时撤销，不能只等待下一次全量重建。

关键词检索擅长精确术语，向量检索擅长语义近似，混合检索和 reranker 可以组合两者，但是否有效要按数据集验证。评估先判断正确证据是否进入 top-k，再判断生成答案是否被证据支持；检索失败与生成幻觉需要分别归因。

权限过滤应在召回或可证明安全的检索阶段执行，不能先取回无权限内容再要求模型“不要说”。保存 query、过滤条件、候选文档版本、得分、重排结果与最终引用，才能复现一次错误回答。无可靠证据时系统应拒答或转人工，而不是用模型常识补齐内部事实。
