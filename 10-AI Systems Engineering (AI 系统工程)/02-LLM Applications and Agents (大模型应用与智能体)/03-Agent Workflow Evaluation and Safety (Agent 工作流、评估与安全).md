> [!abstract] 学习目标
> 将 Agent 视为模型参与决策的有状态工作流，使用显式状态、受限工具、检查点和评估控制可靠性，而不是依赖无限自主循环。

> [!summary] 核心摘要
>
> 将计划、调用、观察和结束条件写成可追踪状态；每一步有预算、权限和恢复语义。高风险动作需要确定性规则或人工批准。

# 工作流状态

任务至少记录输入、当前步骤、已执行工具、结果摘要、预算、错误和终止原因。长任务将检查点持久化，重启后从安全状态恢复，不能重复不可逆副作用。

~~~text
plan -> validate -> act -> observe -> decide
          |                         |
       reject/approve            finish/fail
~~~

状态机比自由循环更容易测试和解释。能够用普通程序确定完成的步骤，不必交给模型决定。

# 可靠执行与预算

每个任务限制步骤数、墙钟时间、并发、token 和费用，并把取消信号传播到模型、工具与后台任务。工具调用使用幂等键；重试要区分模型服务失败、工具瞬态错误、业务拒绝和结果未知，不能把所有失败都从头执行。

每步记录 `pending/running/succeeded/failed/unknown`、输入摘要、工具调用 ID、结果引用和剩余预算。只有确定未执行的步骤可以直接重试；状态为 `unknown` 时先查询工具侧结果或转人工处理。检查点应在不可逆动作前后持久化。

并行只用于相互独立且结果可安全合并的步骤。转账、发信、创建工单等外部动作通常无法真正回滚，因此需要预览、确认、审批、幂等和人工接管；补偿操作不等于数据库事务回滚。

# 权限与工具边界

工具 schema 只解决结构，不证明调用被授权。运行时还要根据用户、租户、任务和具体资源检查权限，并限制目标、金额、行数、出网、时间和调用次数。模型输出始终是不可信提议，高风险参数由确定性代码重新验证。

提示、检索文档和工具结果都可能携带间接提示注入。系统指令不能被当成秘密保险箱；Secret 不进入 prompt，工具凭据使用最小权限短期身份，未经信任的数据不能自行扩大 Agent 权限。
# 评估体系

离线集覆盖正常、边界、拒答、提示注入、工具故障和多轮任务。指标分开记录任务成功、步骤效率、工具正确率、事实性、安全、延迟和费用。

线上通过采样审查、用户反馈和业务结果发现漂移，但不能直接把敏感生产对话无边界地作为训练数据。

# 安全与人工控制

高风险动作展示计划、目标对象和影响，让用户明确批准。批准令牌绑定具体参数和有效期，避免一次确认授权后续任意操作。
