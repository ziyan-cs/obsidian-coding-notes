> [!abstract] 学习定位
> 本篇说明如何通过解题、验证和复盘形成算法能力，不安排比赛日期、每周题量或阶段任务。实际学习顺序统一由 Hub 的 Study Cycle 管理。

> [!summary] 核心摘要
>
> 算法练习的核心不是累计题数，而是从约束识别模型，写出正确性依据，验证边界，并把失败提炼成可迁移的错误模式。

# 解题闭环

1. 从输入规模、数据范围、是否有序和答案性质推导复杂度预算。
2. 写出最直接方案，明确瓶颈，再选择数据结构或算法优化。
3. 在编码前说明状态、不变量、转移或贪心依据。
4. 用最小值、最大值、重复值、空输入和反例验证。
5. 提交后复盘首次错误，而不是只保存最终代码。

# 错误分类

| 错误 | 复盘重点 |
| --- | --- |
| 模型识别错误 | 哪个约束提示了二分、图、DP 或滑动窗口 |
| 正确性错误 | 缺少什么不变量、状态定义或反例 |
| 边界错误 | 下标、空集、溢出、重复值还是初始化 |
| 复杂度错误 | 哪一层循环、容器操作或状态数超出预算 |
| 实现错误 | 接口、所有权、迭代器或模板是否可复用 |

# 重做标准

重做时不查看旧代码，先口述模型与复杂度。能够独立写出主干、解释正确性并通过自建边界样例，才说明错误模式已经被修复。若只记住某道题的代码，应换一道结构相同、表面不同的题检验迁移。

# 模板的使用边界

模板只保存稳定、容易写错且跨题复用的骨架，例如二分边界、并查集、最短路和背包循环顺序。每个模板必须写清前置条件、复杂度、溢出风险和一个反例；不能用模板替代问题建模。

# 能力证据

一次有效练习至少留下题意约束、方案选择、错误原因、复杂度和一个自建测试。需要安排练习时，从 Study Cycle 选择当前最薄弱模型，不在本文件维护周计划或比赛日历。
