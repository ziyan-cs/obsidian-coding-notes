> [!abstract] 学习目标
> 把阅读、编码、复盘和项目证据组成可持续闭环；知道哪些内容应进入错因记录、模板或正式笔记，并用 Hub 统一安排学习而不在模块中散落日程。

# 学会的判定标准

“看懂”只表示材料熟悉。一个知识点达到可用状态，至少能：

1. 不看原文解释它解决的问题与核心机制；
2. 从前提推导结论，而非复述句子；
3. 写出最小实现或操作步骤；
4. 给出反例、边界和失效条件；
5. 在陌生表述中识别同一模型；
6. 用测试、命令输出或项目结果提供证据。

背记仍有价值，但应背术语、接口契约、关键不变量和高频决策，而不是整段答案。

# 一次学习单元

## 进入前

- 写出本篇要回答的 2–4 个问题；
- 回忆已有知识，不先翻答案；
- 明确本次产物：代码、实验记录、解释或设计图。

## 学习中

- 每个结论追问前提与反例；
- 手动推演一个正常样例和一个边界样例；
- 运行代码或命令，记录环境与实际输出；
- 遇到陌生术语时先建立与已有概念的关系。

## 结束时

- 合上笔记口述核心因果链；
- 完成文末检查理解；
- 写一个最小实验或实现；
- 将尚不能独立解释的点标为下一次复查对象。

具体日期与任务量只放在 Hub/Study Cycle；专题正文保留知识和完成标准，不维护分散日程。

# 错误记录：保存原因，不抄题解

高价值错误记录使用如下结构：

```text
问题/场景：一句话描述约束
首次判断：当时选择了什么方案
失败证据：哪个样例、日志或测试推翻了它
根因分类：模型 / 不变量 / 边界 / 复杂度 / API / 工程环境
正确原则：可迁移的一条规则
最小反例：下次可快速检验的输入
验证方式：重做题、测试或实验
```

不要保存完整题面和最终答案堆积。若错误只属于某一篇知识点，把原则修订回正文；若跨多个专题重复出现，再保留在统一错误记录中。

# 模板库的边界

模板只适合稳定、跨题复用且容易写错的骨架。每个模板必须同时包含：

```text
用途与前置条件
输入/输出契约
核心不变量
复杂度
溢出、所有权和边界风险
一个能区分错误写法的反例
```

优先使用标准库与项目中经过测试的实现。算法正文已经保存二分、并查集、最短路、背包等代码时，不再复制一份“万能模板”；重复副本会漂移。真正需要复用时，把它提升为有测试的代码库，而不是继续复制 Markdown 片段。

# 复习应以检索和迁移为中心

有效复习不是重新顺读全文，而是：

1. 根据标题尝试回忆结构；
2. 回答检查问题并解释因果；
3. 重做最小实验或陌生变体；
4. 对照原文只修正缺口；
5. 根据表现调整下一次复查，而不是机械遵守旧日期。

学习队列属性不等于正文事实核验：

- `study_stage`：待学、首次学习、复习阶段或已巩固；
- `review_due`：下一次实际学习、主动回忆或实践的日期；
- `studied_on`：首次有效学习的真实日期，不能用排期日预填。

完成学习后写入 `studied_on`，按实际掌握程度更新 `study_stage` 与 `review_due`。完全不会可短期复查；能解释但不会实践，安排变体练习；连续多次独立完成后再拉长间隔。正文事实的版本与来源单独记录在相关段落。具体任务统一由 Hub 和查询脚本呈现。

# 从笔记走向项目证据

知识只有进入决策才产生工程价值：

| 知识 | 最小证据 |
|---|---|
| 数据结构 | 实现、复杂度与边界测试 |
| 操作系统 | `strace/perf/proc` 实验记录 |
| 网络 | 抓包、超时与重试实验 |
| 数据库 | SQL、执行计划和并发事务复现 |
| 分布式 | 故障注入、幂等与恢复证据 |
| 工程工具 | 可重复构建、测试与诊断脚本 |

项目复盘应说明约束、备选方案、为何选择、测量结果和失败经历，而非只列技术名词。

# 知识库维护规则

- 一篇笔记回答一个稳定主题，标题结构反映因果而非句子数量；
- 新内容优先合并到最接近的主题，只有形成独立学习目标才新增文件；
- 易变信息注明版本和验证日期，稳定原理与工具命令分开；
- 发现错误直接修正文，并保留必要的“为什么旧说法错”；
- 链接只连接真正的前置、后续或对照主题，不创建装饰性链接墙；
- 定期删除重复摘要、废弃计划和已被正文吸收的临时记录。

# 自我验收

学习一个专题后，尝试在没有笔记的情况下完成：

- [ ] 用 3–5 分钟讲清问题、机制和边界；
- [ ] 写出或操作最小样例；
- [ ] 构造一个反例或故障场景；
- [ ] 解释时间、空间或资源成本；
- [ ] 回答“为什么不用另一种方案”；
- [ ] 留下可重复验证的证据。

若只能完成前两项，说明处于理解阶段；能够迁移到陌生问题和项目约束，才接近掌握。

# 检查理解

1. 为什么复制完整题解通常不是高价值错题记录？
2. 什么内容应该留在专题正文，什么内容适合统一错误记录？
3. `content_verified` 与学习进度字段有什么区别？
4. 怎样证明自己掌握了知识，而不只是熟悉笔记措辞？

> [!summary] 本篇结论
> 刻意练习依靠主动回忆、即时反馈、错误归因和陌生迁移。笔记负责稳定知识，Hub 负责时间安排，代码与实验负责提供证据；三者分工能避免计划、模板和正文互相污染。
