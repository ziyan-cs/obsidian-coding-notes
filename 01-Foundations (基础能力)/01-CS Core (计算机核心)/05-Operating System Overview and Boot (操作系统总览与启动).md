> [!abstract] 学习目标
> 从“保护与复用硬件”理解操作系统，分清系统调用、异常、中断与上下文切换，并能讲清 UEFI 机器从上电到用户空间的启动链。

# 操作系统解决什么问题

裸机只提供指令、内存和设备。操作系统在硬件与应用之间提供两类能力：

- **抽象（abstraction）**：把 CPU 抽象为进程/线程，把物理内存抽象为虚拟地址空间，把块设备抽象为文件。
- **资源管理（resource management）**：决定谁在何时使用 CPU、内存和 I/O，并隔离故障与权限。

常见内核职责包括进程调度、虚拟内存、文件系统、设备驱动、网络协议栈、权限检查和进程间通信。库与命令行工具属于用户空间，不等于内核。

```text
应用与运行库
    │  API：fopen、std::thread、malloc …
    ▼
系统调用接口：openat、clone、mmap …
    │  受控进入内核
    ▼
内核：调度 / 内存 / VFS / 网络 / 驱动
    │
    ▼
CPU / RAM / 存储 / 网卡
```

## 机制、策略与隔离

- **机制（mechanism）**说明“能怎么做”，例如定时器中断、页表和上下文保存。
- **策略（policy）**说明“选择谁”，例如调度顺序和页面回收对象。
- **保护（protection）**依靠 CPU 特权级、页表权限和内核校验；用户程序不能只凭一个地址访问任意内存。

这种分离使同一机制可以服务不同目标：吞吐优先、交互延迟优先或实时截止期优先。

# 用户态如何进入内核

## 四种事件不要混淆

| 事件 | 触发方式 | 例子 | 返回位置 |
|---|---|---|---|
| 系统调用（system call） | 用户程序主动、同步 | `read`、`mmap` | 调用之后 |
| 异常（exception） | 当前指令执行引发、同步 | 缺页、除零、非法指令 | 修复后重试或终止 |
| 中断（interrupt） | 外部设备或定时器、异步 | 网卡完成、时钟中断 | 被打断的执行流 |
| 上下文切换（context switch） | 调度器更换运行任务 | A 线程换成 B 线程 | B 的历史执行点 |

系统调用会发生**特权级转换（mode transition）**，但不必然更换线程；只有调度器选择另一个任务时才是上下文切换。缺页也不一定涉及磁盘：匿名页首次分配、写时复制和文件页已在缓存时都可能很快完成。

以 Linux/x86-64 为例，运行库把系统调用号和参数放入约定的寄存器后执行 `syscall`。CPU 切到内核入口，内核保存必要状态、验证参数并执行服务，最后返回用户态。`int 0x80` 是历史/兼容路径，不能代表所有现代架构。

> [!important] API 不等于系统调用
> C/C++ 的 `write()` 通常是 libc 包装；`std::cout` 还包含格式化与用户态缓冲。一次高层 API 调用可能不进入内核，也可能触发多次系统调用。用 `strace` 观察，不要凭函数名猜测。

## 成本来自哪里

系统调用成本取决于架构、缓解措施、缓存、参数检查和是否阻塞，不能背固定纳秒数。常见优化方向是减少往返与复制，例如批量 I/O、缓冲、`readv/writev`，但收益必须在真实负载下测量。

# 内核组织方式

| 方式 | 思路 | 优点 | 代价/边界 |
|---|---|---|---|
| 宏内核（monolithic） | 多数核心服务在内核态 | 内部调用直接、生态成熟 | 内核缺陷影响面大 |
| 微内核（microkernel） | 尽量把服务移到用户态，通过 IPC 协作 | 隔离清晰、组件可替换 | IPC 与系统设计更复杂 |
| 混合设计（hybrid） | 按目标折中 | 可兼顾生态与模块化 | 分类边界并不绝对 |

Linux 通常称宏内核，但支持可加载模块和用户态服务；“宏内核”不等于所有功能都静态编进一个文件。

# 从上电到用户空间

现代 UEFI 机器的典型链路如下，具体发行版与平台会有所差异：

```text
复位向量
  → 固件初始化 CPU、内存与必要设备
  → UEFI Boot Manager 按启动项加载 EFI 程序
  → OS loader 加载内核和 initramfs，准备启动参数
  → ExitBootServices：操作系统接管机器
  → 内核初始化内存、调度器、驱动和根文件系统
  → 运行 PID 1
  → 服务管理器启动系统服务与登录环境
```

Legacy BIOS 的 MBR/引导扇区链路仍可能存在，但不能用它解释所有现代机器。Secure Boot 校验启动组件的信任链；它提高启动完整性，不等同于磁盘加密。

`initramfs` 是早期用户空间：它可加载根文件系统所需驱动、解锁加密卷或组装 RAID，再切换到真正根文件系统。PID 1 还承担孤儿进程回收和系统服务生命周期管理等特殊职责。

# 动手验证

```bash
strace -c ls >/dev/null        # 汇总系统调用
cat /proc/$$/status            # 当前 shell 的内核视图
cat /proc/cmdline              # 内核启动参数
dmesg --level=err,warn         # 内核启动与运行期告警
systemd-analyze                # 使用 systemd 时观察启动阶段
```

验证时记录内核版本、发行版、虚拟机/物理机和命令参数。`dmesg` 可能受权限策略限制。

# 检查理解

1. 为什么系统调用一定有模式转换，却不一定有上下文切换？
2. 缺页异常为什么可能完全不访问磁盘？
3. UEFI、OS loader、内核、initramfs 和 PID 1 各负责哪一段？
4. 为什么“减少系统调用次数”不是无条件的性能结论？

> [!summary] 本篇结论
> 操作系统通过抽象、隔离和策略复用硬件。系统调用、异常和中断描述进入内核的原因；上下文切换描述运行实体是否改变。启动则是一条逐步移交控制权并建立运行环境的信任与初始化链。
