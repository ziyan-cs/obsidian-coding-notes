## Performance Fundamentals (性能基础)

> [!abstract] 核心考点：延迟 vs 吞吐量、Amdahl 定律、CPU 性能公式、性能度量指标

## 延迟 vs 吞吐量

| 概念 | 定义 | 例子 |
|------|------|------|
| **延迟** (Latency) | 完成单个任务所需时间 | 一次 HTTP 请求用时 100ms |
| **吞吐量** (Throughput) | 单位时间完成的任务数 | 每秒处理 10000 个请求 |

优化往往需权衡：增加缓存降低延迟但消耗更多内存，多线程提升吞吐但可能增加延迟。

## CPU 性能公式

```
CPU 时间 = 指令数 × CPI × 时钟周期时间
```

| 因子 | 含义 | 受谁影响 |
|------|------|---------|
| **指令数** | 程序执行的指令总数 | 编译器、ISA、算法 |
| **CPI** | 每条指令平均时钟周期数 | 微架构、数据 locality |
| **时钟周期** | 每个时钟周期的时间 | 硬件工艺、频率 |

**优化思路：** 减少任一因子即可提升性能，但通常相互牵制（如更复杂的指令集可减指令数但可能增加 CPI）。

## Amdahl 定律

```
加速比 = 1 / ((1 - P) + P/S)
```

P = 可优化部分占比，S = 该部分的加速比

**核心含义：** 即使将 90% 部分提速 100 倍，整体加速也不会超过 10 倍——**瓶颈决定最终性能**。

```cpp
// 实际意义：不要过早优化非瓶颈部分
// 花 10 小时将 10% 的部分提速 10 倍 → 整体仅加速 1.1 倍
// 花 1 小时将 90% 的部分提速 2 倍 → 整体加速 1.8 倍
```

## 常用性能指标

| 指标 | 含义 | 场景 |
|------|------|------|
| QPS / TPS | 每秒查询/事务数 | 服务器吞吐量 |
| P99 延迟 | 99% 请求在此时间内完成 | 长尾延迟 |
| IPC | 每周期指令数（CPI 倒数） | CPU 效率 |
| FLOPS | 每秒浮点运算次数 | 科学计算 |
| IOPS | 每秒 I/O 操作数 | 存储性能 |

## System Thinking (系统思维)

> [!abstract] 核心考点：> 局部性原理、空间/时间局部性、缓存友好的代码、并发与并行的区分

## 局部性原理

程序倾向于在一段时间内集中访问某些数据或指令：

| 类型 | 含义 | 例子 |
|------|------|------|
| **时间局部性** | 刚访问过的数据很可能再次被访问 | 循环变量、计数器 |
| **空间局部性** | 刚访问过的数据附近也可能被访问 | 数组顺序遍历 |

```cpp
// 缓存友好（空间局部性好）：顺序访问
for (int i = 0; i < n; i++)
    sum += a[i];          // 一次 cache line（64B）加载 16 个 int

// 缓存不友好：跳跃访问
for (int i = 0; i < n; i++)
    sum += a[big_jump[i]]; // 每次可能在不同 cache line

// 更严重的：按列遍历行主序数组
for (int j = 0; j < n; j++)     // ❌ 每步跨一整行，空间局部性极差
    for (int i = 0; i < n; i++)
        sum += matrix[i][j];
```

## 并发 vs 并行

| 概念 | 定义 |
|------|------|
| **并发** (Concurrency) | 多个任务在**同一时间段内**交替执行（逻辑同时） |
| **并行** (Parallelism) | 多个任务在**同一时刻**同时执行（物理同时） |

单核 CPU 可以并发但不能并行；多核 CPU 可以并发且可以并行。

## 缓存友好编程原则

1. **顺序访问内存**（利用空间局部性）
2. **将热点数据紧缩存放**（struct 中频繁访问的字段放一起）
3. **分治时优先切分数据而非任务**（保持每个子任务的数据局部性）
4. **避免 false sharing**（多线程写同一 cache line 的不同变量 → 性能暴跌）

## 权衡思维

计算机科学的核心就是权衡（Trade-off）：

| 权衡 | 典型场景 |
|------|---------|
| 时间 vs 空间 | 缓存 vs 内存，压缩 vs 原始 |
| 延迟 vs 吞吐 | 批处理 vs 实时处理 |
| 一致性 vs 可用性 | CAP 定理 |
| 精度 vs 速度 | float vs double，近似算法 |
| 通用 vs 专用 | CPU vs GPU vs ASIC |

> [!tip]- **工程要点**
> 系统思维意味着理解"没有免费的午餐"——每项优化都有代价，关键是识别真正的瓶颈（Amdahl 定律），并从多层级（算法→代码→编译→架构）分析问题。
