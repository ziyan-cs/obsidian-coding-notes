> [!abstract] 学习目标
> 用区间长度确定依赖顺序，通过“最后一次合并/切分/选择”推导转移，并理解 `O(n³)` 优化不能脱离数学条件。

# 区间 DP 的统一模型

区间 DP 常令 `dp[l][r]` 表示闭区间 `[l, r]` 的最优值、方案数或可行性。大区间依赖更短子区间，因此通常按长度递增：

```cpp
for (int length = 2; length <= n; ++length) {
    for (int left = 0; left + length <= n; ++left) {
        int right = left + length - 1;
        for (int split = left; split < right; ++split) {
            // 用 [left, split] 和 [split+1, right] 更新
        }
    }
}
```

推导时问“最后一次操作是什么”：最后合并哪两个子区间、最后切在哪里、最后戳破哪个元素。这样能保证剩余部分是独立子问题。

# 石子合并

相邻石子每次合并代价为两堆重量和。令 `dp[l][r]` 为合成一堆的最小代价，最后一次在 `k` 与 `k+1` 间合并：

```text
dp[l][r] = min(dp[l][k] + dp[k+1][r] + sum(l,r))
```

区间和用前缀和 `prefix[r+1] - prefix[l]` 在 `O(1)` 取得。基础状态 `dp[i][i] = 0`，总复杂度 `O(n³)`、空间 `O(n²)`。

若石子是环形排列，可复制数组后枚举长度为 `n` 的区间；不能简单固定从下标 0 切开，因为最优合并可能跨过该边界。

# 矩阵链乘

矩阵 `A_i` 维度为 `d[i-1] × d[i]`。改变括号不改变结果，却改变标量乘法次数：

```text
dp[l][r] = min(
    dp[l][k] + dp[k+1][r] + d[l-1] × d[k] × d[r]
)
```

使用足够宽的整数类型并检查维度乘法溢出。若要恢复括号方案，另存使最优值成立的 `split[l][r]`，再递归输出。

# 回文类区间状态

判断子串是否回文：

```text
pal[l][r] = (s[l] == s[r]) && (r - l <= 2 || pal[l+1][r-1])
```

它可作为回文分割、最长回文子串等问题的预处理。最少回文切割更适合一维状态 `cuts[i]` 表示前缀，而不必强行把最终答案也写成区间 DP。状态维度应服务依赖，而非服务分类标签。

# 戳气球：枚举最后一个

若枚举第一个戳破的气球，左右邻居会动态变化，子问题不独立。反过来令 `dp[l][r]` 表示开区间 `(l,r)` 内全部戳完的最大收益，并枚举最后戳破的 `k`：此时它的邻居固定为 `l`、`r`。

```text
dp[l][r] = max(dp[l][k] + value[l]×value[k]×value[r] + dp[k][r])
```

这是“改变最后一次决策，使子问题独立”的典型技巧。

# 优化必须有证明

四边形不等式、Knuth 优化、分治优化可把部分 `O(n³)` 转移降到 `O(n²)` 或更低，但需要代价函数满足单调决策点、Monge 等条件。题型长得像区间 DP 并不自动满足；先证明条件或引用可靠定理，再实现优化。

# 复杂度与实现边界

- `n³` 是否可接受取决于 `n`、语言、常数和时限，不能用固定阈值代替估算。
- `O(n²)` 表可能先被内存限制；`n=10⁴` 时矩阵已经非常大。
- 初始化 `INF` 后做加法要防止溢出，只从可达状态转移。
- 记录决策可恢复方案，但会增加空间和代码复杂度。

# 检查理解

1. 为什么区间 DP 通常按长度从短到长？
2. 石子合并的区间和为什么每次都要加入？
3. 戳气球为什么枚举最后一个比第一个更容易分解？
4. 为什么不能见到 `O(n³)` 就直接套四边形不等式优化？

> [!summary] 本篇结论
> 区间 DP 通过最后一次操作把大区间拆为已知小区间。状态边界、遍历长度和切分点共同决定正确性；高级优化只有在代价结构满足严格条件时成立。
