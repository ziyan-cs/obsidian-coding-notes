> [!abstract] 学习目标
> 把递归看成显式状态转移，把回溯看成深度优先枚举决策树；能够设计路径、选择集合、终止条件、撤销操作和安全剪枝。

# 从递归到状态空间树

递归函数必须同时具备：

1. **状态**：当前已经做出的选择和剩余可选范围；
2. **基例**：何时得到答案或确定失败；
3. **递归推进**：每次调用让问题严格接近基例；
4. **返回语义**：返回一个值、是否成功，还是把答案写入外部集合。

回溯（backtracking）是在状态空间树上执行 DFS：选择一个分支、递归探索、撤销选择，再进入下一分支。

```text
                空路径
          /        |        \
        选 A       选 B      选 C
       /   \       ...       ...
   继续选  停止
```

时间复杂度通常与搜索树节点数有关，可能是指数或阶乘级；“用了递归”不自动意味着 `O(n)`。

# 通用骨架

```cpp
void search(State& state, std::vector<Answer>& answers) {
    if (is_complete(state)) {
        answers.push_back(make_answer(state)); // 通常需要复制快照
        return;
    }

    for (Choice choice : choices(state)) {
        if (!is_valid(state, choice)) continue;
        apply(state, choice);
        search(state, answers);
        undo(state, choice);                    // 与 apply 严格对称
    }
}
```

若每层使用局部值传递状态，可能不需要显式 `undo`，但复制成本会上升。共享可变路径更高效，也更容易因提前返回或异常遗漏撤销；优先让修改范围清晰。

# 子集、组合与排列

## 子集：每个位置选或不选

```cpp
void subsets_dfs(const std::vector<int>& a, std::size_t start,
                 std::vector<int>& path,
                 std::vector<std::vector<int>>& out) {
    out.push_back(path);
    for (std::size_t i = start; i < a.size(); ++i) {
        path.push_back(a[i]);
        subsets_dfs(a, i + 1, path, out);
        path.pop_back();
    }
}
```

共有 `2^n` 个子集，仅输出结果就需要 `Ω(n·2^n)` 级别的数据量（按复制出的元素总数计）。

## 组合：用 start 消除顺序重复

从 `[start, n)` 选下一个元素，保证下标递增，因此 `{a,b}` 不会以 `{b,a}` 再出现。若还需选 `need` 个，剩余元素不足时可停止：

```text
n - start < need  → 不可能完成
```

## 排列：位置不同视为不同顺序

排列通常用 `used[i]` 表示元素是否已选，或在原数组上交换当前位置与候选位置。所有元素互异时有 `n!` 个结果。交换法必须在递归返回后交换回来。

# 重复元素去重

输入含重复值时，先排序便于识别同层重复：

```cpp
if (i > start && a[i] == a[i - 1]) continue; // 组合/子集的同层去重
```

“同层去重”避免同一位置选择相同值产生重复分支；“同枝不可复用”由 `start` 或 `used` 控制。两者不是一回事。排列去重还要结合 `used[i-1]` 的状态，确保相同值按固定顺序进入路径。

# 剪枝：必须保持完备性

安全剪枝要求被剪分支不可能产生所需答案：

- 和已超过目标，只在后续增量非负时成立；
- 当前代价已不优于已知最优，要求未来代价不会下降；
- 剩余候选数量不足；
- 约束传播已发现冲突，如 N 皇后列与对角线被占用；
- 记忆化记录“同一状态已求解”，前提是状态键包含影响未来的全部信息。

启发式排序（先尝试更可能成功的选择）可更早找到答案，却不改变最坏复杂度；若错误地把启发式当成剪枝，会漏解。

# 回溯、DFS 与动态规划

- DFS 描述遍历顺序；回溯强调选择与撤销，通常枚举解空间。
- 若不同路径反复到达同一状态，可加入 memo 形成记忆化搜索。
- 当状态依赖关系可按拓扑顺序迭代计算时，可改写为自底向上的 DP。
- 若只需一个可行解，找到后可向上传播成功并提前停止；若需全部解，不能提前返回。

# 工程边界

- 深度不受控时递归可能栈溢出，需要显式栈、深度限制或输入约束。
- 返回全部组合可能比搜索本身更耗内存，可改为 callback、生成器或逐个消费。
- 全局变量会污染多次调用和并发执行；把路径与答案放进对象或参数。
- 测试空输入、重复元素、无解、唯一解、所有分支都可行和最大深度。

> [!summary] 本篇结论
> 回溯是对决策树的系统枚举：状态必须足够描述未来，选择与撤销必须对称，剪枝必须证明不会漏解。输出规模往往已经是指数级，因此复杂度要按搜索树和结果量分析。
