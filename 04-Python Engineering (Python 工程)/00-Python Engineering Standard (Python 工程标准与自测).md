> [!abstract] 完成标准
> Python 先承担自动化、测试、数据处理和后端辅助。学完后应能交付可重复运行、可测试、失败可诊断的小型工程，而不是只会在交互环境里拼 API。

本模块以 Python 3.11+ 为示例基线（`asyncio.TaskGroup`、`asyncio.timeout` 从 3.11 提供）；实际项目仍应在 `pyproject.toml` 中声明并测试支持的版本范围。

# 语言与运行环境

- [ ] 能解释对象、名称绑定、可变性、复制、作用域、闭包、迭代协议、生成器、类、装饰器和上下文管理器。
- [ ] 能使用虚拟环境与 `pyproject.toml` 管理依赖，复现安装并区分运行依赖和开发依赖。
- [ ] 能正确处理容器、路径、文本编码、JSON/CSV、日期时间、配置、命令行参数与子进程。
- [ ] 能用异常表达失败语义，保留错误上下文，并确保文件、连接等资源可靠释放。

# 质量与自动化

- [ ] 能为正常、异常和边界路径编写 pytest 测试，合理使用 fixture、参数化、test double、性质测试、fuzz 与集成测试。
- [ ] 能使用类型标注、格式化、lint 和静态检查提升接口可读性，但不把类型标注误认为运行时强制约束。
- [ ] 能编写幂等脚本，支持 dry-run、日志、退出码和配置覆盖，避免误操作文件或外部服务。
- [ ] 能把一次性命令整理为清晰的模块、入口与测试，而不是不断扩大的单文件脚本。

# 后端辅助能力

- [ ] 能安全调用 HTTP API，设置超时、重试边界、认证和响应校验。
- [ ] 能处理日志与 CSV，输出可复核的统计结果，并保留输入、参数与失败记录。
- [ ] 能理解线程、进程和 asyncio 的并发模型，为 I/O 任务设置有界并发、取消和超时。
- [ ] 能为 C++/Go 项目编写数据生成、接口检查、基准汇总或部署辅助工具。

# 交付验收

- [ ] 完成一个 CLI 工具：配置、日志、类型、测试、错误处理和 README 齐全。
- [ ] 完成一个并发 I/O 工具：并发有上限，失败可重试，进程可中断退出。
- [ ] 在干净环境中从零安装并运行，结果可重复，敏感信息不进入仓库。
- [ ] 能解释关键设计取舍，并指出当前实现的性能与可靠性边界。

# 综合自测

1. 可变默认参数为什么危险，默认参数在什么时候求值？
2. context manager 解决了什么问题，它与 `try/finally` 是什么关系？
3. asyncio 并不会让 CPU 计算自动并行，原因是什么？
4. 一个批量改文件脚本怎样设计，才能在路径错误或中途失败时仍然安全？
