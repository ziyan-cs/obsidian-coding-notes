> [!abstract] 学习定位
> 执行用户代码、插件或 Agent 工具时，应假设其会读取秘密、耗尽资源并攻击网络；沙箱必须限制能力、资源和生命周期。

> [!summary] 核心摘要
>
> 进程、容器、虚拟机和专用沙箱提供不同隔离强度。选择依据是对手能力与失败影响，并配合只读文件系统、网络白名单、资源配额、短期身份和强制终止。

# 威胁模型

区分偶然错误、恶意脚本、已知逃逸利用和内核级对手，并列出宿主机、云凭据、用户数据、内部网络、构建缓存与其他租户等资产。

只限制文件系统但允许任意出网，代码仍可能外传数据；只禁网但不给 CPU/内存上限，仍可能拒绝服务。

# 隔离层次

| 机制 | 优点 | 主要边界 |
| --- | --- | --- |
| 语言运行时限制 | 启动快 | 逃逸风险高，不能替代 OS 隔离 |
| 独立进程 | 生命周期清晰 | 共享内核与用户权限 |
| 容器 | 部署成熟、资源控制方便 | 共享宿主机内核 |
| 用户态内核/沙箱运行时 | 缩小宿主机攻击面 | 兼容性和性能成本 |
| 虚拟机/微虚拟机 | 隔离更强 | 启动、镜像和运维成本更高 |

高风险、多租户、任意代码通常需要比普通业务容器更强的边界。

# 执行协议

~~~text
validate -> isolated workspace -> least privilege
         -> CPU/memory/time/network limits
         -> bounded output -> destroy -> audit
~~~

禁止默认继承宿主环境变量、SSH agent、云 metadata 身份和 Docker socket。工具参数使用 schema 校验；模型生成的命令与用户命令具有相同的不可信等级。

# 执行面与控制面协议

提交任务时固定镜像/运行时、命令、只读输入、输出上限、CPU/内存/PID/磁盘/时间和网络策略。控制面不直接信任沙箱返回的状态；它按 task ID 验证结果、截断输出并清理资源。

```text
untrusted job -> queue -> isolated worker -> artifact quarantine
                    |       |
                 policy   no host credential / bounded egress
```

容器共享宿主内核，面对恶意代码时可选择强化容器、用户态内核、microVM 或独立节点。边界选择取决于攻击者能力和数据价值，而不是“用了 Kubernetes”。即使发生逃逸，节点身份最小权限、默认拒绝出网、无宿主挂载和短生命周期也应限制影响。

验证包括 fork bomb、磁盘填满、超长输出、网络扫描、读取 metadata、恶意系统调用和超时进程树。终止任务必须清理子进程、卷和临时凭据，并留下可审计原因。

# 逃逸后的第二道防线

即使沙箱被突破，网络分段、短期凭据、最小权限、只读数据和异常检测也应限制影响。定期升级内核与运行时，并通过故障注入验证 timeout、强制终止和清理路径。
