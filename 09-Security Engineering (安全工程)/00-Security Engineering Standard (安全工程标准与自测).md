> [!abstract] 完成标准
> 后端安全的目标不是背攻击名称，而是在设计、实现、交付和运行阶段持续控制风险：识别资产与信任边界，落实最小权限，验证滥用路径，并在失守时限制影响和恢复业务。

# 应用安全

- [ ] 能画数据流、资产、主体、入口与信任边界，用威胁模型指导优先级而非罗列漏洞。
- [ ] 能区分认证、会话和授权，设计凭据的签发、存储、过期、撤销、轮换与审计。
- [ ] 能防范对象级与字段级越权、注入、CSRF、XSS、SSRF、文件处理和资源耗尽，并编写负向测试。
- [ ] 能在 C++、Go、Python 中识别各自的内存、并发、解析、依赖和错误处理风险。
- [ ] 能把威胁转换为 ASVS/API 安全要求、负向测试和发布证据，说明扫描工具无法覆盖的业务风险。

# 身份、云与供应链

- [ ] 能用工作负载身份、短期凭据、RBAC/ABAC 和最小权限控制人、服务与自动化主体。
- [ ] 能说明哈希、MAC、加密、签名与 TLS 分别保证什么，不自行设计密码协议。
- [ ] 能管理 Secret 的创建、分发、使用、轮换和泄漏响应，不把秘密写入源码、镜像或日志。
- [ ] 能追踪依赖、镜像和构建来源，执行扫描、签名、SBOM、策略检查与受控升级。

# 隔离、检测与响应

- [ ] 能根据威胁选择进程、容器、虚拟机或专用节点隔离，并限制文件、网络、身份、资源和生命周期。
- [ ] 能设计可调查的安全事件模型，记录 actor、action、resource、result 与关联 ID，同时保护秘密和隐私。
- [ ] 能把检测规则映射到具体威胁与基线，控制误报、漏报、告警路由和处置时限。
- [ ] 能完成分级、止损、证据保全、根除、恢复、验证和无责复盘，并通过演练检验预案。

# 综合自测

完成本专题后，至少留下一份可复核的工程证据包：为自己的后端项目画一页数据流与信任边界，选出三条高风险路径（例如登录、订单读取、文件/URL 处理），逐条写明资产、滥用方式、服务端控制、负向测试和日志事件。再模拟一次凭据泄漏，记录撤销、轮换、影响面查询和恢复验证的步骤。没有项目可用时，用本地虚构数据和隔离环境演练；不要对非授权系统测试。

1. 一个 URL 抓取接口如何形成 SSRF？仅做域名黑名单为什么不够，网络和身份层还应怎样限制？
2. 服务账号密钥进入公开仓库后，为什么删除提交不等于完成处置？请给出完整响应顺序。
3. 已通过认证的用户读取了别人的订单，这是认证还是授权问题？应在哪些层编写负向测试？
4. 一个扫描器报告数百个依赖漏洞时，怎样按可达性、资产影响和补偿控制决定发布门禁？
5. 运行 AI Agent 生成的代码时，你会怎样选择隔离边界并限制出网、凭据和资源？
