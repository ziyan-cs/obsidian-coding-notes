> [!abstract] 完成标准
> 本模块要求把应用代码、操作系统和网络协议连成一条因果链：请求为什么等待、数据在哪里排队、事件如何被唤醒、故障怎样被观测。

# Linux 运行时

- [ ] 能解释进程、线程、调度、虚拟内存、文件描述符与系统调用的关系。
- [ ] 能使用进程、文件、网络、日志和性能工具观察真实运行状态。
- [ ] 能说明阻塞、非阻塞、同步、异步以及 I/O 多路复用不是同一维度的概念。
- [ ] 能处理信号、资源限制、守护进程和优雅退出的基本问题。

# 网络协议

- [ ] 能从链路、IP、TCP/UDP 到 HTTP/TLS 解释一条请求的封装与传输过程。
- [ ] 能解释 TCP 建连、可靠传输、流量控制、拥塞控制、关闭与常见异常状态。
- [ ] 能说明 DNS、HTTP 缓存、连接复用、TLS 证书校验和协议版本差异。
- [ ] 能用抓包验证握手、重传、窗口、延迟和应用层报文，而不是只背状态机。

# 服务器网络编程

- [ ] 能正确使用 socket、bind、listen、accept、connect、读写和关闭接口。
- [ ] 能解释 select/poll/epoll、LT/ET、Reactor、buffer 与事件循环的责任边界。
- [ ] 能处理半包、粘包、短读写、慢客户端、连接超时、背压和惊群问题。
- [ ] 能设计连接生命周期、线程模型、任务队列和优雅关闭流程。

# 故障排查

- [ ] 能区分 DNS、建连、TLS、首字节、传输和应用处理造成的延迟。
- [ ] 能根据 `ss`、`lsof`、`strace`、抓包、日志和指标逐层缩小问题范围。
- [ ] 能解释高 CPU、高负载、端口耗尽、连接堆积和大量 TIME_WAIT 的可能原因。
- [ ] 能构造最小实验验证网络参数或 I/O 模型，而非直接套用调优参数。

# 后端安全

- [ ] 能画出服务的数据流与信任边界，识别资产、攻击入口和故障影响。
- [ ] 能区分认证、会话与授权，设计 token/session 的过期、撤销和轮换流程。
- [ ] 能防范对象级越权、字段越权、注入、CSRF、XSS、SSRF 和资源耗尽，并写出负向测试。
- [ ] 能管理 Secret、最小权限、依赖供应链与安全日志，发生泄漏后可以撤销和审计。
# 综合自测

1. epoll 返回“就绪”意味着什么，为什么仍需处理短读写和 `EAGAIN`？
2. 一次 HTTPS 请求首次访问比复用连接慢，额外时间可能花在哪里？
3. 服务端 accept 很快但业务响应很慢，你会按什么顺序收集证据？
4. 对端关闭连接时，本端的 read、write 和协议状态可能如何变化？
