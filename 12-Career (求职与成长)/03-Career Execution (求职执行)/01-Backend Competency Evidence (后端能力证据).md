> [!abstract] 学习定位
> 本篇把后端能力转换为可展示、可追问、可复现的证据，不再维护按月份划分的 C++ 学习路线；能力顺序统一由 Hub Roadmap 管理。

> [!summary] 核心摘要
>
> 求职材料中的每项能力都应对应代码、测试、运行结果、故障记录或设计取舍。会背概念但无法展示如何验证，不算可靠证据。

# 证据层级

| 层级 | 证据 |
| --- | --- |
| 理解 | 能用自己的话说明问题、机制和边界 |
| 实现 | 有最小代码、测试和可重复运行命令 |
| 工程 | 有构建、日志、指标、错误处理和维护边界 |
| 诊断 | 有一次真实或注入故障的定位过程 |
| 决策 | 能说明替代方案、取舍和不适用条件 |

# C++ 与系统能力

资源模型用 RAII、copy/move、智能指针与异常安全代码证明；并发用竞态复现、同步依据和退出协议证明；性能用固定环境、负载、profile 与前后对照证明。Linux 与网络能力应能沿进程、文件、套接字、协议和内核事件定位故障。

# 服务与数据能力

一个服务至少展示契约、业务不变量、事务、缓存或消息边界、timeout、重试、幂等、日志指标和优雅关闭。数据库与分布式结论需要执行计划、故障实验或恢复记录，而不是组件名称。

# 项目表达

每个主项目准备目标、约束、请求路径、个人负责部分、最困难问题、证据和遗留风险。数字必须能还原测试环境；“提升很多”“高并发”“保证一致性”等表述必须落到指标和边界。

# 维护方式

本页只定义证据标准。当前需要补哪项证据写入 Study Cycle；已经完成的材料放进项目 README、测试报告或作品集，不在 Career 模块复制另一份日程。
