> [!abstract] 本篇要点
> 用数量级、单位和边界条件快速自检估算；平台常数应现场查询，不能把某台机器的取值当成语言或协议保证。

# 数量级

| 值 | 十进制近似 | 常见用途 |
| --- | ---: | --- |
| `2^10 = 1024` | 约 1 千 | KiB 中的换算因子 |
| `2^20 = 1,048,576` | 约 1 百万 | MiB 中的换算因子 |
| `2^30 = 1,073,741,824` | 约 10 亿 | GiB 中的换算因子 |

十进制 `MB = 10^6 B`，二进制 `MiB = 2^20 B`。估算带宽和存储时写清单位、峰值与协议开销；例如 `1,000,000 次/s × 1,000 B/次 = 1 GB/s`，只表示应用负载的十进制基线。

# 整数与位边界

- `n` 位无符号整数范围为 `0..2^n-1`；固定宽度类型应先确认实现提供，例如 `std::uint32_t`。
- `char` 的有符号性、`long` 的宽度及整数提升随实现而变；用 `sizeof`、`std::numeric_limits` 和编译器目标配置核对。
- `x & (x - 1)` 清除最低位的 1，前提是按合适的无符号类型处理且 `x != 0`；`x & -x` 用于取最低位的 1，也应明确类型和零值语义。
- `std::string` 是字节序列，UTF-8 字节数、Unicode 码点数与用户感知字符数不能混用。

# 时间与网络

| 量 | 结论 | 边界 |
| --- | --- | --- |
| 时间换算 | `1 s = 1000 ms = 10^6 μs = 10^9 ns` | 延迟估算仍需区分平均与尾部 |
| TCP/UDP 端口 | 16 位编号，`0..65535` | 端口 0 保留；本机绑定端口 0 通常表示请求系统选端口 |
| 以太网 MTU | 常见配置为 `1500 B` | 路径 MTU、隧道和实际链路可不同 |
| IPv4/TCP MSS | 无选项且 MTU 为 1500 B 时常见 `1460 B` | 实际头部与路径条件决定结果 |
| TIME_WAIT | 保留一段时间以处理旧报文与关闭重传 | 不背固定秒数，按系统与配置核对 |

IANA 的 [端口注册表](https://www.iana.org/assignments/service-names-port-numbers/)区分系统、用户和动态端口。Linux 绑定低端口通常受 `CAP_NET_BIND_SERVICE` 或系统配置约束；不能概括为“必须 root”。

# Linux 现场查询

文件描述符 `0/1/2` 通常是进程的标准输入、输出和错误输出；具体进程仍可重定向。`PATH_MAX`、`PIPE_BUF`、信号编号和 `open`/`epoll` 宏值不应作为跨平台固定数背诵。

```bash
getconf PATH_MAX .
getconf PIPE_BUF .
kill -l
```

这些命令查询当前环境；需要编写可移植程序时，应以目标平台文档和实际 API 返回值为准。

# 考察题目

## 1. 动手题

估算一百万 QPS、1 KB 响应的带宽和日流量，写明十进制/二进制单位与峰值假设。

> [!note]- 验收要点
> 约 1 GB/s、86.4 TB/日的十进制量级；还需考虑协议开销与峰值系数。

## 2. 机制追问

估算系统容量时，常数或数量级记错会导致什么？如何自检？

> [!note]- 参考答案
> 可能让带宽、存储和并发预算差一个数量级；写明单位、假设与计算过程，用上下界和量纲检查结果。
