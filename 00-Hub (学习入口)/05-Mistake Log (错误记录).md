> [!abstract] 记录理解偏差
> 只记容易重犯、代价高或暴露认知缺口的错误。笔记正文出错则放入[审计与迁移队列](07-Vault%20Audit%20%26%20Migration%20Queue%20%28%E5%AE%A1%E8%AE%A1%E4%B8%8E%E8%BF%81%E7%A7%BB%E9%98%9F%E5%88%97%29.md)。

# 怎么记录

每条用几行写清“误判 → 正确理解 → 下次检查”，必要时附最小复现与关联笔记。日期可省略，不逐日打卡，也不复制整篇答案。

```md
**简短问题名**
- 误判与原因：我把什么理解成了什么？
- 正确理解：成立条件与边界是什么？
- 验证：最小输入、关键代码或反例。
- 下次检查：遇到 ___ 时，先检查 ___。
- 关联笔记：链接到对应主题。
```

# 常见检查点

| 遇到什么 | 先检查什么 |
| --- | --- |
| 指针、引用、视图与回调 | 谁拥有资源，何时失效？ |
| 共享状态与锁 | 有无数据竞争，锁顺序是否一致？ |
| goroutine、channel 与异步任务 | 谁取消和回收，是否可能永久等待？ |
| Python 可变对象 | 是否共享同一个对象，复制是否符合预期？ |
| 数据更新、消息与重试 | 重复执行会不会产生重复副作用？ |
| 性能结论 | 基线、输入规模与测量条件是否相同？ |

# 我的记录

在此追加真实问题。理解稳定后，将有价值的解释写回专题，合并重复记录；复习日期仍维护在对应笔记属性中。
