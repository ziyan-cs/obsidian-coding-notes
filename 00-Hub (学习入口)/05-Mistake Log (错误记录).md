> [!abstract] 用途
> 只记录可能重犯、代价高或暴露认知缺口的错误，并把它提炼成下一次可执行的检查规则。

# 记录模板

```md
## YYYY-MM-DD — 简短标题
- 触发场景：
- 错误判断与根因：
- 正确模型：
- 最小反例 / 复现：
- 下次检查：看到 ___ 时先检查 ___。
- 关联笔记：根路径 Markdown 链接
```

# 高频检查

| 场景 | 先问 |
| --- | --- |
| 指针、引用、view、回调 | 所有者是谁？何时失效？ |
| 并发共享状态 | 是否有数据竞争、锁顺序或退出问题？ |
| Go goroutine / channel | 谁负责取消？是否可能永久阻塞？ |
| Python 可变对象与依赖 | 是否共享状态？环境能否复现？ |
| 数据库更新、消息消费、重试 | 是否幂等？重复执行会怎样？ |
| 性能优化 | 是否有基线、测量方法和目标指标？ |

每周从新增记录中提炼少量规则；稳定规则写回对应专题笔记。复习日期只改关联笔记的 `review_due`，不在本页另建日程。
