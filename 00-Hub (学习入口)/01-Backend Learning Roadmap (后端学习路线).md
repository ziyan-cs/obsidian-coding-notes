# 阶段 1：现在开始（前 12 周）

## C++：每周 3 次

1. 生命周期与所有权：RAII、Rule of Zero/Five、智能指针、移动语义。
2. 并发正确性：mutex、condition variable、atomic、内存序先理解“为什么错”。
3. 工程基本功：编译链接、CMake target、测试、Sanitizer、gdb。

**验收**：能解释 `shared_ptr` 的线程安全边界；能修复一个资源泄漏/数据竞争小例子；能用 CMake 编译并跑测试。

## Python：每周 2 次

1. 环境：解释器、虚拟环境、包、命令行参数。
2. 工具：文件、路径、JSON、CSV、正则、HTTP 请求。
3. 质量：pytest、类型标注、日志。

**验收**：写出三个自己会用的脚本：批量文件整理、日志/CSV 分析、HTTP 接口检查。

## 算法与基础：每周 2 次

- 算法按题型做 3–5 题，必须记录错误模式，而非只记录题解。
- OS / 网络 / MySQL 只学能解释 C++ 或服务行为的内容。

# 阶段 2：Go 从零到服务（第 4–6 月）

学习顺序：语法和模块 → `error` / `context` → goroutine / channel / `sync` → testing → HTTP / JSON / middleware → 数据库。

**验收项目**：一个有路由、参数校验、测试、结构化日志、优雅关闭的 HTTP API；不急于引框架，先掌握标准库。

# 升级规则

- 某主题能脱稿讲 3 分钟、改写最小例子、答对自测题，才从 `review` 升为 `solid`。
- 连续两周没有可运行产物，则减少阅读量，改做一个 30 分钟小实验。
- 新工具、框架或版本信息先查一手文档，记录验证日期；见 [[06-Sources & Freshness Policy (来源与时效规则)]]。

# 30 秒复盘

学习路线的目标不是“把目录看完”，而是在两年内反复完成可验证的小闭环：理解一个概念，写最小实现，用测试或实验观察边界，再把它放进项目和面试表达。C++ 强化底层与性能直觉，Go 形成服务交付能力，Python 提升测试和自动化效率。

# 零基础阅读路径

先阅读问题与最小例子，再理解机制与边界，最后做验证或练习。无法复述因果关系时，先回到输入、状态和输出。

# 常见误区

- 只背结论而不说明它成立的前提、失败模式和替代方案。
- 不通过最小代码、测试、测量或项目现象验证，就把理解误当成掌握。
