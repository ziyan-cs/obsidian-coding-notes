# 按文件夹推进的主线

下文用“一级/二级目录序号 + 中文主题”定位左侧文件树，例如“03/02 对象与资源模型”。同一阶段中的支线与主线交错学习，不必先读完一个顶层目录；升级以可运行证据为准，而不是以打勾数量为准。

1. **起步：把程序跑起来。** 先沿 01/01 计算机核心 → 03/01 C++ 语言基础 → 03/02 对象与资源模型走；04/01 Python 基础同时推进。02/01 Git 与交付、02/02 构建与依赖从第一次写程序就介入；01/02 算法与数据结构每周保持练习，01/03 数学与推理按所遇问题补入。01/04 基础实践和 11/01 项目方法负责把阅读变成实验记录。阶段产物是一份能在干净环境构建、测试、由 Python 脚本验证的 C++ 小程序。
2. **系统主线：理解资源、并发与网络。** 按 03/03 现代 C++ → 03/04 STL 与数据结构 → 03/05 并发与性能 → 03/06 工程实践加深；与之交错阅读 06/01 Linux 运行时 → 06/02 网络协议 → 06/03 服务器网络编程。02/03 验证与诊断在每次实验中使用，而不是最后补学。阶段产物可以是 C++ 网络组件或小型服务，保存调试、sanitizer、压测与故障证据。
3. **服务交付：先会验证，再用 Go 做服务。** 完成 04/02 质量与自动化 → 04/03 后端辅助 → 04/04 Python 实践的基本闭环后，进入 05/01 Go 基础 → 05/02 并发与运行时 → 05/03 Web 服务；随后用 07/01 MySQL 与 SQL → 05/04 数据集成 → 05/05 Go 实践 → 07/02 缓存与代理构建短链接等服务。Python 继续承担测试与数据采集，不与 Go 争夺服务主线。升级证据是含持久化、权限/输入边界、超时、测试和可观测性的可运行 API。
4. **多组件系统：从故障与恢复认识分布式。** 先 07/03 消息与流，再 07/04 分布式基础；进入 08/01 容器与 Kubernetes 后先做 08/03 可靠性工程，确有平台化需求再深入 08/02 平台工程。09/01 应用安全应从第一个 Web 项目就应用，09/02 身份、云与供应链在部署时加深，09/03 隔离、检测与响应接到运行演练中。用 11/02 后端项目里的 IM、秒杀或配置中心选择一项深做，证明重复、乱序、依赖故障与恢复。
5. **AI 扩展：让后端能力承接模型。** 先 10/01 AI 基础 → 10/02 大模型应用与智能体，掌握评估、RAG、工具授权与失败语义；真实容量或部署需求出现后再进 10/03 AI 基础设施。11/02 安全 AI Agent 平台可作为扩展项目，但不能挤掉前面的数据库、网络与服务可靠性。阶段产物要有数据集、引用与权限测试、任务成本和可回退版本。
6. **求职表达贯穿两年。** 12/04 决策记录从做项目起随手积累；形成可复现的项目证据后再系统进入 12/01 面试表达，具备数据与分布式经验后进入 12/02 系统设计；12/03 求职执行在真实招聘窗口前集中推进。最终保留两项能演示、能解释取舍和故障、数字可复核的主项目，而不是五项只写架构图的项目。

这些阶段可以重叠：算法练习、工程英语、复习和项目证据始终伴随主线。若某阶段的产物不能运行或无法解释失败边界，就回到对应文件夹补缺，不因为计划日期到了而强行进入下一阶段。

# 统一掌握标准

一个主题达到以下条件才算进入可用状态：

1. 不看正文能讲清问题、机制和边界。
2. 能写最小例子、实验或故障复现。
3. 能解释失败发生在哪一层，以及如何取得证据。
4. 能在项目中说明为什么选它，以及什么情况下不选。

# 防止主线漂移

- AI 不替代算法、系统和后端基础。
- Kubernetes 不替代 Linux、网络与服务生命周期。
- 安全不是孤立专题，要进入身份、数据、交付和运行。
- 新框架先说明它解决的问题、引入的成本和退出方案。
- 连续多个学习周期没有可运行产物时，停止扩展主题，回到当前最小交付。
