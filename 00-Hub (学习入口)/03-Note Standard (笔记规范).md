> [!abstract] 写作标准
> 一篇讲清一个完整主题，让首次学习者看得懂，让再次查阅者找得到。标题展示知识关系，正文解释机制与边界。

# 文件与属性

文件和目录使用 `序号-English (中文)`，笔记加 `.md`。正文不再重复文件名作标题。常规结构保持“模块 → 专题 → 笔记”；模块的 `00-... Standard` 用于掌握标准与综合自测。

学习进度只维护 `study_stage` 与 `review_due`。未学用 `backlog`，首次学懂后改为 `D1` 并手动填写次日复习日期；尚未学懂时可用 `learn`。后续复习用 `D3 / D7 / D14 / D30 / D60`，稳定掌握用 `solid`，Hub 等参考页用 `reference`。既有 `tags` 只作分类，不要求随学习修改。

```yaml
study_stage: backlog
review_due:
```

`review_due` 在 Obsidian 中统一设为**日期**属性：未安排时保留空值；首次学懂后，将 `study_stage` 改为 `D1`，再把 `review_due` 填为次日的真实日期（`YYYY-MM-DD`）。属性类型配置保存在 `.obsidian/types.json`，随笔记库一起使用。阶段更新见[间隔复习系统](/00-Hub%20(学习入口)/02-Spaced%20Review%20System%20(间隔复习系统).md)。

# 内容与排版

- **叙述顺序**：先说明问题与术语，再解释机制、例子与边界。代码交代输入、预期结果和验证点，建议交代适用前提。
- **大纲层次**：一级标题组织主要知识单元，二级解释其组成；几句话的补充用正文或列表。并列主题同级，不为凑格式增加标题。
- **减少重复**：摘要不与核心结论、30 秒回答反复复述。合并笔记后重写过渡，清除旧导航和拼接痕迹。
- **阅读观感**：段落、列表、表格与代码块之间留空行；callout 少量使用。ASCII 图难以对齐时改用表格或简明列表。
- **拆分边界**：主题能够独立解释、验证和查阅时才拆分。专题目录尽量有至少 3 篇实质笔记，不为数量制造薄篇。

# 链接与事实

链接显示简明中文标题，地址使用仓库根路径；空格写成 `%20`，括号保留原样，不加反斜杠。例如：

[学习周期](/00-Hub%20(学习入口)/09-Study%20Cycle%20(学习周期).md)

只链接必要的前置、对照或实践，文末少量关联即可。修改名称或路径后同步入链，不在每篇末尾堆一份目录。
