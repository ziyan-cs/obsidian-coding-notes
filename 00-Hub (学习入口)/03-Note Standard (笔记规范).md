> [!abstract] 核心原则
> 文件名已经承担文章标题；正文大纲只展示知识结构。标题不是段落装饰，而是能够独立复述的知识模块。

# 文件与属性

文件统一使用 `序号-English (中文).md`，正文不再重复书写与文件名相同的一级标题。

```yaml
---
status: learning       # learning | stable
confidence: medium     # low | medium | high
verified: YYYY-MM-DD   # 最近一次编辑审阅日期
review_due: YYYY-MM-DD # 可选：下一次建议复习日期
tags: [topic/example]  # 可选：确有检索价值时使用
---
```

`verified` 不表示所有外部事实都在当天重新验证。涉及版本或 API 时标记 `VERSION_CHECK` 并写明核验入口；性能数字必须保留环境与方法，标记 `MEASURE_LOCALLY`。

# 正文骨架

正文按主题选用模块，不要求机械填满：问题与心智模型、核心机制、工程使用、边界与排查、实践与复习。一级模块的 `00` 文件只写完成标准与综合自测，不复制文件目录。

一篇普通笔记通常保留 **2～7 个一级模块**；短主题允许两个完整模块，长篇参考页按检索结构组织，不为满足数量强行加标题。二级标题用于同一模块内的机制分解；三级标题只在确实存在多个并列步骤时使用，避免四级及更深层级。

# 标题规则

- 标题下只有一两句话，且没有独立模型、代码、表格或边界时，合并到相邻章节。
- 不把一句话结论、注意、示例、常见误区机械提升为一级标题；优先使用正文、列表或 callout。
- 一级标题超过 8 个时必须重新检查：合并同一因果链，或将独立主题拆成新文件。
- 一个文件出现两条互不依赖的学习主线时应拆分，例如 TLS 与 HTTP/2。
- 拆分后的每篇仍需形成完整闭环，禁止几行代码或一个术语独占一篇。
- 只看一级标题，应当能够讲出整篇的因果主线。

# 复述检查

普通教学笔记不使用 `# 30 秒回答`。需要压缩表达时，放入默认折叠且不进入大纲的 callout：

```md
> [!summary]- 复述检查：学完后再展开
> 用 80～150 字说明问题、核心机制和适用边界。
```

- 回答必须针对当前主题，不能使用通用占位句。
- 能力标准、计划、模板和错题本通常不需要复述检查。
- 求职表达类笔记可以保留 `## 30 秒表达`，因为表达训练本身就是正文。
- 摘要说明学习目标；复述检查用于学完后的主动回忆，两者不能重复。

# 示例、自测与实践

- 示例必须说明输入、预期输出和它验证的结论。
- 自测只保留能判断是否掌握本专题的问题；通用提问直接删除。
- 能运行的主题优先给命令、代码、测试、抓包、日志或压测步骤。
- 工程结论必须写出前提、失败场景和替代方案。
- 性能数字必须附环境与测量方法，不能把数量级印象写成稳定事实。

# 拆分与合并标准

适合拆分：存在独立因果链，子主题有独立前置知识、实践方式和复习价值，或文件大纲已经无法表达主线。

适合合并：子文件只有定义和几行示例，多个文件共享同一问题与实践闭环，或拆分只是为了文件数量整齐。

知识目录原则上至少包含 3 篇实质笔记；不足时优先并入相邻目录，不创建占位页。

# 链接与来源

- 文末只保留确有知识依赖的前置、对照或实践链接；普通笔记不重复链接 `00` 标准页。
- 内部链接使用根路径 Markdown 链接，确保 Obsidian 与 GitHub 都可访问。
- 稳定原理优先引用规范、论文或官方手册；易变工具信息优先引用当前官方文档。
- 链接用于表达知识依赖，不保留散落的旧式指向句，也不把文末堆成链接仓库。
