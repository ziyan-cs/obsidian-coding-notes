> [!abstract] 核心原则
> 一篇笔记讲清一个相对完整的主题。标题呈现知识结构，正文承担解释；入口页只给标准和自测，不复制专题内容。

# 文件与属性

- 文件名使用 `序号-English (中文).md`；正文不重复文件名作为 H1。
- 学习笔记只维护 `study_stage`、`review_due`；首次完成后可加一次 `studied_on`。Hub 参考页使用 `study_stage: reference`。
- `study_stage` 取值：`backlog / learn / D1 / D3 / D7 / D14 / D30 / D60 / solid / reference`。只有近期已排任务才写 `review_due`。
- 易变事实在相关段落注明版本、来源或验证方法；使用 `VERSION_CHECK` 或 `MEASURE_LOCALLY` 标记尚待核验项。

```yaml
study_stage: learn
review_due: YYYY-MM-DD
```

# 正文与大纲

- 开头用一段短摘要说明主题、机制和边界；计划、模板、错误记录等操作页可省略。
- 通常保留 2–7 个一级主题；标题下只有一两句话时并入正文。二级标题分解机制，三级仅用于必要的并列步骤，避免更深层级。
- 合并拼接痕迹与重复结论；“一句话总结”“核心结论”“30 秒回答”不重复表达同一内容。
- 标题应概括知识单元，不把示例、注意事项或单句提示升成同级标题。只看大纲应能复述文章主线。
- 每个专题目录的 `00-... Standard` 只说明目标和综合验收，不复制目录清单或正文。

# 教学与观感

- 面向首次系统学习者：先解释问题与术语，再讲机制、例子、边界和验证方式；避免只给结论或孤立代码。
- 例子写明输入、预期结果及验证点；工程建议交代前提、失败情形和替代方案。
- Obsidian 中保持段落、表格、代码块留白；callout 只用于摘要、警告或可折叠补充，不给每段套框。
- ASCII 图仅在关系难以用文字说明时使用；中文宽度不可靠时改用列表或表格。

# 拆分、链接与来源

- 只有当主题有独立前置、因果链和实践闭环时才拆分；定义加几行代码不单独成篇。知识目录原则上至少有 3 篇实质笔记。
- 文末只链接真实前置、对照或实践内容；不堆导航链接，不保留失去上下文的“详见”句。
- 内部链接用根路径 Markdown 链接；易变 API、工具行为和性能结论优先引用规范、官方文档或可复现实验。
