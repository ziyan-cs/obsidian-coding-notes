> [!abstract] 一句话结论：从 2026-09-07 起，先用两周补稳 C++ 与算法基础，再用两周建立 Python 工程基础；复习日期只在实际学过并完成回忆练习后写入。

# 使用规则

每个学习日按 **2.5–3 小时** 设计：新内容 90–120 分钟，脱离笔记复述与最小实践 45–60 分钟，旧内容回忆 20–30 分钟。若当天只有 90 分钟，保留“旧内容回忆 + 一个新主题的最小实践”，不要硬塞第二篇新笔记。

新学一篇后，先不把它看作掌握。关闭笔记，回答“它解决什么问题、核心机制是什么、何时不能用”；能答出再写 `review_due`。间隔以实际表现决定：

| 结果 | 下一次 `review_due` |
| --- | --- |
| 答不出或最小练习失败 | 下一个学习日 |
| 能复述主线，但边界不清 | 4 天后 |
| 能独立写最小例子 | 10 天后 |
| 能解释取舍并在练习/项目中用过 | 21 天后 |
| 21 天后仍能答出 | 45 天后 |

这不是死板的记忆算法：**失败缩短、成功拉长、未学习不排期**。间隔练习和主动提取通常比反复重读更有利于长期保持，但具体间隔应随你的正确率调整。

# 计划后的推进顺序

第 5–7 周：Python 工程项目收尾，同时每周复习 C++ 资源与并发基础。第 8–13 周：C++ 后端工程、Linux 运行时与网络协议。第 14–18 周：MySQL、Redis、消息与一致性。**Go 放在 Python 工具链和 C++ 后端主线稳定之后**，以第一个 Go HTTP 服务为入口，而不是提前背 goroutine 细节。

# 每日收尾

1. 用 `List-ReviewDue.ps1` 查看今天与逾期笔记。
2. 先做 20–30 分钟主动回忆，再学习当天新主题。
3. 仅对今天实际学习且完成自测的笔记，写入 `review_due: yyyy-MM-dd`。
4. 错误、困惑或没做出的练习写入错误记录；下周计划根据它调整。
