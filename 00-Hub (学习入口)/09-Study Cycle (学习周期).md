> [!abstract] 唯一任务面板
> 本页把课程、项目和自由学习时间统一为一套可执行节奏。知识模块只保存脚本需要的学习属性，不再各自维护周计划。

# 每日入口

```powershell
.\List-ReviewDue.ps1
.\List-ReviewDue.ps1 -All
```

默认显示逾期、当天和明天；`-All` 查看完整首月队列。开始新内容前，先处理当天到期复习。

# 首月一周节奏

| 星期 | 可用时段 | 主任务 | 负荷边界 |
| --- | --- | --- | --- |
| 周一 | 20:45–22:30；下午另有项目推进 | C++ 中等篇，晚上理解、次日项目中应用 | 一篇，不追加系统新课 |
| 周二 | 课程密集，另有 Linux/Shell Lab | 20～30 分钟到期复习 | 不开新篇 |
| 周三 | 21:00–22:30；下午项目推进 | Python 基础 | 一篇加最小可运行示例 |
| 周四 | 09:00–12:00 | C++ 重篇与调试实验 | 一篇重文，预留至少 60 分钟编码 |
| 周五 | 12:30–13:50；14:00 Python Lab | Python 基础与实验衔接 | 一篇，直接带入 Lab |
| 周六 | 13:30–17:00 | 计算机组成/系统基础与实验 | 一篇重文，必须有观察证据 |
| 周日 | 13:30–17:00；20:30 周复盘 | 复习、短实践笔记、项目输出 | 最多一篇短文；先复习再新增 |

三条线不是互相争抢时间：C++ 训练资源与工程模型，Python 提供自动化和验证能力，计算机组成与系统基础解释程序为何这样运行。以 2026-09-23 为重新排期的起点，首月仍保留 28 篇、周二不加新课、周日先复习的负荷；已经废弃的旧日期不再留在单篇属性里。首月之后按实际进度滚动安排，不预填整个大学的死日期。

# 首月：2026-09-23 至 2026-10-22

这是启动段，不是两年总计划。已排好的 28 篇笔记由 `List-ReviewDue.ps1 -All` 按日列出；本页只规定**文件夹焦点、学习顺序与实践产物**，避免同一份日程在两处失去同步。目录缩写沿用路线图的“一级/二级序号”。

| 时段 | 文件夹焦点 | 本段留下的东西 |
| --- | --- | --- |
| 09/23–09/27 | 04/01 Python 基础；03/01 C++ 语言基础 → 03/02 对象与资源模型；01/01 计算机核心 | 多文件 C++ 小程序，Python 建环境并读取其输出，画出代码到运行的链路 |
| 09/28–10/04 | 03/02 对象与资源模型；04/01 Python 基础 → 04/04 Python 实践；01/01 数据表示 | 对照 C++ 值、指针与 Python 对象；用小实验记录溢出、编码或生命周期错误 |
| 10/05–10/11 | 03/03 现代 C++；04/01 Python 基础 → 04/02 质量与自动化；01/01 程序构建与执行 | 一份从预处理到链接的观察记录，加上 Python 日志采集与最小测试 |
| 10/12–10/18 | 03/02 RAII 与资源；04/01 文件/异常 → 04/02 测试；01/01 存储层级与 I/O | C++ 资源封装与 Python context manager 对照；测试正常退出和异常退出 |
| 10/19–10/22 | 03/03 智能指针；04/01 CLI；02/02 构建与依赖 | CMake 构建的 C++ 程序 + Python 驱动脚本 + 测试命令 + 一页可复现说明 |

首月的优先级是让 C++、Python、计算机核心三条线在**同一份可运行产物**里相遇。若某篇重文未完成，不为赶表格而跳过实验；把该主题顺延到下一个同类学习时段，并同步修改对应笔记的 `review_due`。周日以补缺和整合作为第一任务，不强制新增笔记。

# 首月之后：按 6～8 周推进块滚动

每轮只设一个**主文件夹群**、一个**支撑文件夹群**和一个可演示成果；具体读到哪篇，根据前一轮的错误与项目瓶颈再排进 `review_due`。按照 [后端学习路线](/00-Hub%20(学习入口)/01-Backend%20Learning%20Roadmap%20(后端学习路线).md) 依次推进：

1. **C++ 与系统块**：03/03–03/06 配合 06/01–06/03、02/03；做网络或并发组件，拿到 sanitizer、日志与压测证据。
2. **Python、Go 与数据块**：先补 04/02–04/04，再走 05/01–05/05 与 07/01–07/02；做带 MySQL、缓存、测试与优雅关闭的服务。
3. **分布式、云与安全块**：07/03–07/04 → 08/01、08/03 → 09/01–09/03；在 11/02 中深做一个多组件项目，演练故障、权限和恢复。08/02 平台工程仅在真正需要平台化时深入。
4. **AI 与求职块**：10/01 → 10/02，容量需求出现后再进 10/03；用 11/02 验证评估、权限与成本。12/04 决策记录全程积累，12/01–12/03 在有项目证据后集中训练。

每轮前半段建立模型与最小实现，中段补反例、测试和故障注入，后段整理 README、原始指标与取舍记录。**结束条件**不是“读完文件夹”，而是能演示产物、解释两个失败路径，并能指出下一轮最重要的知识缺口。若未达到，继续当前块而不是机械切换主题。

首月后的时段仍沿用上表的可用时间，但主任务替换为当前推进块；例如进入 Go 与数据块后，周一/周四的 C++ 时段可用于 Go 服务或数据库实验，C++ 改为每周一次维护性实践。不要把“首月星期表”当成未来两年的固定科目表。

# 学完后的属性更新

排期状态：

```yaml
study_stage: learn
review_due: 2026-09-23
```

真正学完后才写 `studied_on`（实际完成日），把 `study_stage` 改为 `D1`，`review_due` 改为次日。之后按 `D1 → D3 → D7 → D14 → D30 → D60 → solid` 推进；答不出机制、边界或最小代码则退回 D1。达到 `solid` 后删除 `review_due`。

# 首月验收

- [ ] C++：能解释对象、生命周期、copy/move、RAII 与智能指针，并有可运行资源封装。
- [ ] Python：能建立环境、组织模块、处理数据和文件、编写 CLI，并驱动外部程序。
- [ ] 计算机组成：能从数据表示讲到编译执行、存储层级与 I/O，且有至少两个实验结果。
- [ ] 综合：CMake 构建 C++ 程序，Python 脚本负责执行、采集和报告，README 可让他人复现。
- [ ] 复习：没有通过单纯修改日期消除逾期；错误与薄弱点已记录。

# 调整规则

- 当天时段被课程或项目占用：只顺延该条线到下一个同类时段，不挤占另一条线。
- 周四或周六的重篇未完成：周日优先收尾，不新增内容。
- 到期项超过 5 篇：暂停新篇，优先当前项目、真实错误和最近学习内容。
- 周日先做到期复习和补缺，有余力再学短实践笔记；必须留下本周项目或实验增量。
- 本页只保存时段、阶段和调整规则；具体到期日以笔记属性为准，由脚本统一展示。
