# 02-Spaced Review System (间隔复习系统)

> [!abstract] 阅读定位
>
> 目标：把“我看过”变为“我能在需要时想起来并写出来”。

## 30 秒回答

**核心结论**：阅读定位 目标：把“我看过”变为“我能在需要时想起来并写出来”。


## 复习节奏

首次有效学习当天记为 `D0`。正常情况下，在 `D1 / D3 / D7 / D14 / D30 / D60` 复习；答不出核心问题就退回 `D1`。

| 复习点 | 做什么 | 通过标准 |
| --- | --- | --- |
| D1 | 不看正文，复述结论与例子 | 说出 3 条结论 |
| D3 | 写出关键代码/流程 | 能写对主干，知道边界 |
| D7 | 做反例或自测 | 不踩本笔记的常见坑 |
| D14 | 连接相邻概念 | 能说出至少一个取舍 |
| D30 | 用于项目/面试表达 | 30 秒内答清用途与边界 |
| D60 | 抽查 | 仍能独立解释；否则重排 |

## 每日 20 分钟执行法

1. 在 Obsidian 搜索 `review_due: YYYY-MM-DD`。
2. 每篇先遮住正文回答“自测题”；再补读遗漏处。
3. 回答流畅：把 `review_due` 推到下一复习点；卡壳：补充误区并设为明天。
4. 单次最多复习 6 篇。积压时优先 C++、项目、近期出错主题。

## 单篇复习记录模板

```md
## Review — YYYY-MM-DD (D7)
- 不看笔记我能回答：
- 漏掉/答错：
- 新增反例或关联：
- 下一次：YYYY-MM-DD
```

## 最小自测格式

- **定义题**：它解决什么问题？
- **机制题**：为什么有效？
- **边界题**：什么时候不该用？
- **实作题**：写出 5–15 行核心代码或画出数据流。

## 状态迁移

```text
seed → learning → review → solid
             ↑        │
             └──答不出─┘
```

- `seed`：尚不能复述。
- `learning`：能跟着例子理解。
- `review`：已进入间隔复习。
- `solid`：两次间隔至少 30 天的复习通过，且可在代码/讲解中应用。

## 从零建立模型

本页主题是 **02-Spaced Review System (间隔复习系统)**。先明确本页解决的具体问题、输入输出和适用边界；再用一个最小例子观察机制如何改变状态或结果。术语必须能被复述为因果关系，而不是孤立定义。

## 最小实践

写一个最小示例、反例或测试，验证本页一条关键结论；记录预期和实际结果。

## 工程检查点

将结论与其前提、失败模式和替代方案一起记忆，不把单次观察当成通用规律。



## 渐进练习

1. **第一步 · 理解**：读：不看正文复述问题、关键状态和适用边界。
2. **第二步 · 实现**：写：做一个最小样例或反例，记录预期与实际结果。
3. **第三步 · 验证**：验：改变一个关键条件，解释结果为何改变，以及何时应换方案。

## 常见误区

- 只背结论而不说明它成立的前提、失败模式和替代方案。
- 不通过最小代码、测试、测量或项目现象验证，就把理解误当成掌握。

## 学习闭环

### 从零复述

- 不看正文，用“问题 → 机制 → 边界”三句话讲清 **02-Spaced Review System (间隔复习系统)**。

### 最小验证

- 写一个最小代码、命令、测试或项目观察，亲自验证本页的一条关键结论。

### 自测

1. 它解决的工程问题是什么？
2. 核心机制在哪个环节生效？
3. 什么时候应当换用另一种方案？
