> [!abstract] 复习原则
> 先主动回忆，再查漏并验证；复习日期从实际完成日滚动，不因延期保留旧日期。

# 复习节奏

首次有效学习为 D0；每次通过后安排下一阶段。答不出核心机制或边界，补学后回到 D1。

| 阶段 | 复习动作 |
| --- | --- |
| D1 | 不看笔记复述概念与例子 |
| D3 | 重写关键代码或流程 |
| D7 | 用反例检查边界与常见误区 |
| D14 | 联系相邻概念，解释取舍 |
| D30 | 用项目或面试语言说明用途与限制 |
| D60 | 独立抽查；稳定掌握后转为 `solid` |

# 每次怎么做

1. 运行 `List-ReviewDue.ps1`，先处理逾期和当天任务。
2. 合上笔记回答自测，再核对遗漏；代码或故障主题要实际验证。
3. 通过：更新 `study_stage` 和 `review_due`；卡住：补缺并设为次日。
4. 积压时优先当前项目、近期错误和必要前置；不要靠改日期假装完成。

只维护 `study_stage`、`review_due`；首次完成时填写一次 `studied_on`。具体字段约定见 [Note Standard (笔记规范)](/00-Hub%20(学习入口)/03-Note%20Standard%20(笔记规范).md)。
