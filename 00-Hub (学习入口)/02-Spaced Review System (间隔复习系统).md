> [!abstract] 学习定位：目标：把“我看过”变为“我能在需要时想起来并写出来”。

> [!summary] 核心摘要
>
> 复习的核心是主动回忆而非重读。先遮住正文回答自测，再用代码或例子验证；答错就缩短间隔，能稳定解释和实践后再延长 `review_due`。

# 复习节奏

首次有效学习当天记为 `D0`。`D1 / D3 / D7 / D14 / D30 / D60` 是便于执行的默认间隔，不是人人、每篇都必须严格命中的定律；答不出核心问题就退回 `D1`，已在项目里频繁使用的内容可以减少机械复习。

| 复习点 | 做什么 | 通过标准 |
| --- | --- | --- |
| D1 | 不看正文，复述结论与例子 | 说出 3 条结论 |
| D3 | 写出关键代码/流程 | 能写对主干，知道边界 |
| D7 | 做反例或自测 | 不踩本笔记的常见坑 |
| D14 | 连接相邻概念 | 能说出至少一个取舍 |
| D30 | 用于项目/面试表达 | 30 秒内答清用途与边界 |
| D60 | 抽查 | 仍能独立解释；否则重排 |

# 每次到期复习

1. 在 Obsidian 搜索 `review_due: YYYY-MM-DD`。
2. 每篇先遮住正文回答“自测题”；再补读遗漏处。
3. 回答流畅：把 `review_due` 推到下一复习点；卡壳：补充误区并设为明天。
4. 概念题可以短时复述；代码、抓包和故障题要留出独立实验时段。一天最多安排 6 篇，积压时优先当前项目、近期出错主题和主线前置知识，不靠改日期假装完成。

# 单篇复习记录模板

```md
## Review — YYYY-MM-DD (D7)
- 不看笔记我能回答：
- 漏掉/答错：
- 新增反例或关联：
- 下一次：YYYY-MM-DD
```

# 最小自测格式

- **定义题**：它解决什么问题？
- **机制题**：为什么有效？
- **边界题**：什么时候不该用？
- **实作题**：写出 5–15 行核心代码或画出数据流。

# 属性流转

```text
learn → D1 → D3 → D7 → D14 → D30 → D60 → solid
          ↑________________________________│
                    答不出则回到 D1
```

- `study_stage`：`backlog / learn / D1 / D3 / D7 / D14 / D30 / D60 / solid / reference`；只有 `learn` 及复习阶段应有到期日。
- `review_due`：下一次需要实际行动的日期，也是 `List-ReviewDue.ps1` 的唯一任务数据源。
- `studied_on`：首次有效学习的真实日期（D0）；排期时不填写，Hub 参考页也不填写。

首次学习完成后，写入当天的 `studied_on`，把 `study_stage: learn` 改为 `D1`，并将 `review_due` 设为次日。后续通过时按 D0 的间隔推进；如果实际复习晚于计划日，下一次到期日不得落在今天之前。失败则回到 `D1` 并设为次日。达到 `solid` 后删除 `review_due`，避免脚本继续列出已结项任务。
