# 当前基线

目录、命名、模块标准和首月学习属性已形成统一约定。这里不使用“百分之百正确”或“全部知识已完成”一类结论：基础结构检查不等于逐条事实审核，运行结果仍以项目实验为准。

# 只收知识库维护问题

发现问题时记录**文件、证据、影响和验收方式**，再按下列顺序处理：

1. **P0 · 错误事实或坏链接**：可复现的错误结论、指向不存在文件的链接、代码示例与正文相矛盾。修正时附来源或最小实验，并检查入链。
2. **P1 · 主线可学性**：缺少前置解释、核心流程或可验证示例，以至于零基础无法继续；先补当前主线，不按文件数凑进度。
3. **P2 · 结构与观感**：标题层级、重复摘要、失去上下文的拼接段落和不必要的专题拆分；改后检查 Obsidian 大纲与链接。
4. **P3 · 时效与低频内容**：API、版本、参数和性能数字按真实项目需要复查。只在相关段落记录版本、核验日期、来源和实验，不把学习进度日期当内容核验日期。

当前没有已确认的全库 P0 条目。若日后发现具体问题，把它写成“位置 → 现象 → 证据 → 修复完成条件”，而不是写“全面优化某模块”。
