> [!abstract] 完成标准
> C++ 主线以资源安全、可预测性能和服务端工程为目标。合格不是会写语法，而是能说明对象何时创建、由谁拥有、何时销毁，以及并发和异常路径下是否仍然正确。

# 语言与资源模型

- [ ] 能解释存储期、作用域、生命周期、值类别、拷贝与移动之间的关系。
- [ ] 能用 RAII 管理内存、文件、锁和连接，优先遵循 Rule of Zero，必要时正确实现 Rule of Five。
- [ ] 能根据所有权选择值语义、引用、裸指针、`unique_ptr`、`shared_ptr` 和 `weak_ptr`。
- [ ] 能解释虚函数、对象布局、模板实例化、异常安全等级及其工程代价。

# 现代 C++ 与 STL

- [ ] 能正确使用类型推导、lambda、concept、optional、variant、ranges 和 coroutine，并知道何时不该用。
- [ ] 能根据访问模式、失效规则、内存布局和复杂度选择容器与算法。
- [ ] 能识别迭代器失效、悬垂引用、未定义行为、隐式转换和异常路径中的资源问题。
- [ ] 能读懂编译错误与模板诊断，构造最小复现而不是盲目修改。

# 并发与性能

- [ ] 能正确管理线程生命周期，使用 mutex、condition variable、future 和 atomic 建立同步关系。
- [ ] 能解释 data race、happens-before、memory order、伪共享与无锁结构的适用边界。
- [ ] 能实现有界线程池、定义拒绝与排空语义，并验证成功提交的任务不会静默丢失；能说明任务永久阻塞时关闭也可能等待。
- [ ] 能通过基准、profiling 和 sanitizer 找到瓶颈或缺陷，不凭直觉声称“更快”。

# 后端工程

- [ ] 能用 CMake 组织多目标项目，接入依赖、测试、静态检查和调试构建。
- [ ] 能实现带日志、配置、超时、连接管理和优雅关闭的网络服务组件。
- [ ] 能解释 buffer、连接池、Reactor、背压和错误处理如何共同决定服务稳定性。
- [ ] 能把崩溃、泄漏、竞态或延迟问题还原为可复现用例并完成根因分析。

# 综合自测

1. `shared_ptr` 的引用计数线程安全，为什么不代表所指对象线程安全？
2. 资源获取到一半抛出异常时，怎样保证已经获得的资源全部释放？
3. 线程池关闭时，如何定义“停止接收、排空任务、立即取消”三种语义？
4. 一次服务延迟升高时，你会怎样区分 CPU、锁、内存、系统调用和下游依赖问题？
5. 哪些关于 vtable、对象对齐、NRVO、标准容器底层结构的说法属于实现观察，而非 C++ 标准保证？
