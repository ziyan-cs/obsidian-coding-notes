# OSI vs TCP/IP  

## 层级关系

| OSI 七层 | TCP/IP 四层 | 作用             | 相关协议/设备                |
| ------ | --------- | -------------- | ---------------------- |
| 应用层    | 应用层       | 面向用户的应用服务      | HTTP/HTTPS、FTP、DNS、SSH |
| 表示层    | -         | 数据格式转换、加密解密    | SSL/TLS                |
| 会话层    | -         | 建立/维护/终止会话     | RPC、NetBIOS            |
| 传输层    | 传输层       | 端到端数据传输、端口寻址   | TCP、UDP                |
| 网络层    | 网络层       | 路由寻址、跨网段传输     | IP、ICMP、ARP            |
| 链路层    | 链路层       | 帧传输、MAC寻址、差错检测 | 以太网、交换机、PPP            |
| 物理层    | 链路层       | 比特流传输、物理介质     | 网线、网卡、集线器              |

## 核心区别

- OSI：理论模型，层次划分更细，了解
- TCP/IP：工业实际标准，简化为四层，是互联网的实际协议栈

# 数据封装与传输流程

> 数据在网络中传输的本质：**发送端逐层封装，接收端逐层解封装** 
## 发送端（封装）

每一层为数据加上本层的头部，向下传递：

| 步骤  | 层级  | 操作                    | 产物        |
| --- | --- | --------------------- | --------- |
| 1   | 应用层 | 生成原始数据（如 HTTP 请求）     | 数据 Data   |
| 2   | 传输层 | 加 TCP/UDP 头部（端口号、序列号） | 段 Segment |
| 3   | 网络层 | 加 IP 头部（源/目标 IP 地址）   | 包 Packet  |
| 4   | 链路层 | 加 MAC 头部（源/目标 MAC 地址） | 帧 Frame   |
| 5   | 物理层 | 转为比特流，通过网线/电磁波发送      | 位 Bit     |

## 接收端（解封装）

从下到上逐层剥去头部，还原原始数据：

物理层 → 链路层（剥 MAC 头）→ 网络层（剥 IP 头）→ 传输层（剥 TCP/UDP 头，校验数据）→ 应用层（应用程序读取）
## 关键概念

- 封装：每层为数据加上自己的头部信息
- 解封装：接收端逐层去掉头部，还原原始数据
- PDU：每一层的数据单位，传输层叫「段」，网络层叫「包」，链路层叫「帧」

# IP 地址 / 端口号 / MAC 地址

> 三者分别回答不同的寻址问题：**去哪台机器 → 哪个进程 → 下一跳谁收**

## 基础定义

- IP 地址：逻辑地址，在全网中定位一台主机
- 端口号：应用标识符，在主机内定位具体进程
- MAC 地址：物理地址，烧录于网卡，在局域网内定位具体设备

## 三者协作：以访问一个网站为例

```txt
用户输入 URL
    ↓
应用层：构造 HTTP 请求，目标端口 80/443
    ↓
传输层：TCP 封装，携带【源端口 + 目标端口】
    ↓
网络层：IP 封装，携带【源 IP + 目标 IP】，负责跨网段路由
    ↓
链路层：MAC 封装，携带【源 MAC + 下一跳 MAC】，负责本段投递
    ↓
每经过一个路由器：IP 不变，MAC 更新为下一跳
    ↓
到达目标主机：逐层解封装，最终交给对应端口的进程
```

## 关键对比
| 特性    | IP地址      | 端口号        | MAC地址       |
| ----- | --------- | ---------- | ----------- |
| 解决的问题 | 跨网段定位设备   | 定位设备上的应用进程 | 局域网内定位设备    |
| 作用范围  | 全局（公网/内网） | 单设备内唯一     | 单局域网内唯一     |
| 是否可改  | 可动态/静态修改  | 可动态分配      | 硬件固化（可软件修改） |
| 对应层级  | 网络层       | 传输层        | 链路层         |

# DNS 域名服务器

> 核心：递归查询vs迭代查询、解析流程、缓存机制

DNS（域名系统）将易读记的域名解析为机器可识别的 IP 地址

## 查询方式

- 递归查询：客户端只问一次本地 DNS，由本地 DNS 代为查询到底，最终返回结果
- 迭代查询：本地 DNS 一层层向上询问，每次只得到下一级服务器的地址，自行继续追问

## 完整解析流程


```txt
用户输入域名
    ↓
1. 浏览器本地缓存
    ↓（未命中）
2. 操作系统 Hosts 文件
    ↓（未命中）
3. 本地 DNS 缓存
    ↓（未命中）
4. 本地域名服务器（递归查询起点）
    ↓
5. 根域名服务器 → 返回顶级域服务器地址
    ↓
6. 顶级域名服务器（如 .com）→ 返回权威域名服务器地址
    ↓
7. 权威域名服务器 → 返回最终 IP 地址
    ↓
8. 本地 DNS 缓存结果（TTL 内有效），返回给客户端
    ↓
客户端用 IP 地址发起实际请求
```

## DNS 缓存

各级节点都会按 TTL（生存时间）缓存解析结果，命中缓存则跳过后续查询步骤，显著提升效率。
